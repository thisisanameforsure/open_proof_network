Open Proof Network — spec site

The build plan for the Open Proof Network — a distributed crowdsourced Lean 4 proof network for open mathematical problems. Every session starts with the constitution; features follow the conventions. The design input is the architecture decisions document (docs/architecture_decisions_v_3_11.html), whose D-numbers are frozen citable identifiers. That document is what is built; everything under engineering/ is how. Specs cite decisions, never restate or override them. This repo is network — gate, API/MCP, website (D-35); the graph repo is the sibling ../open_proof_network_graph, and nothing on this site lands there.

Features — dependency order

Two features are built but not tagged. F03 and F05 each have one acceptance criterion that needs a graph with an unproved node — a real merge (F03-AC13) and a claim round trip against the deployed service (F05-AC19). The live graph holds one node and it is proved, so both wait on F11's intake rather than on any code; adding a node purely to satisfy them would put content in the mathematical record for a test's sake (F05-Q6, decided 2026-09-09).

F06 waits on a GitHub App permission, not on code. T1–T4 are done and verified; T5's criterion (F06-AC15, a real precheck run) is blocked because the App may not dispatch a workflow — 403 Resource not accessible by integration. Granting Actions: read and write is the App owner's act. The steps, and everything either side of the dispatch that is verified against real GitHub, are in engineering/evidence/F06/task-5.txt and engineering/session-notes/2026-09-09-overnight-f06.md.

Each feature is a vertical slice with its own spec, tests, and verification evidence. Status: planned → spec → building → done. Copy features/F00-template.html to draft a new feature spec, then add its row here. The sequence below is the Stage 0 invited run (architecture decisions, Stages) cut into vertical slices, decided 2026-09-07; F00 is the walking skeleton (constitution C2). Rows without a spec file are planned, not committed to in detail.
