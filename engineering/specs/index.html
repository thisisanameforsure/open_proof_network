Open Proof Network — spec site

The build plan for the Open Proof Network — a distributed crowdsourced Lean 4 proof network for open mathematical problems. Every session starts with the constitution; features follow the conventions. The design input is the architecture decisions document (docs/architecture_decisions_v_3_12.html), whose D-numbers are frozen citable identifiers. That document is what is built; everything under engineering/ is how. Specs cite decisions, never restate or override them. This repo is network — gate, API/MCP, website (D-35); the graph repo is the sibling ../open_proof_network_graph, and nothing on this site lands there.

Features — dependency order

Two features are built but not tagged. F03 and F05 each have one acceptance criterion that needs a graph with an unproved node — a real merge (F03-AC13) and a claim round trip against the deployed service (F05-AC19). The live graph holds one node and it is proved, so both wait on F11's intake rather than on any code; adding a node purely to satisfy them would put content in the mathematical record for a test's sake (F05-Q6, decided 2026-09-09).

F06's permission is granted; what it waits on now is the pin. T1–T4 are done and verified. The GitHub App gained Actions: read and write on 2026-09-10, and a real dispatch created a real run — so T5's criterion (F06-AC15) is no longer blocked on anyone's permission. It is blocked on gate-spec.json: the scratch workflow runs the gate at the commit that file pins, and that commit predates gate/precheck/, so the job dies with No module named 'precheck'. Closing it needs the push (which deploys the api) and then a re-pin, which is the gate owner's act (D-4). Evidence, including the run's log, is in engineering/evidence/F06/task-5.txt.

F07 and F08 interleave, by design. F07-T4 needs F08's admission check for a partial's holes (F07 §8), and F08 needs the rest of F07 for everything else — so F08-T1 was built inside F07's slice, on 2026-09-10, and F07-T4 is unblocked by it. The remaining F07 work that is not unblocked is the graph's gate.yml (T1's last line) and T6 — both waiting on the same push and re-pin F06 waits on, since a workflow may only use a gate command the pinned commit understands.

One push and one re-pin unblock four things. Pushing main deploys the api and puts F06–F08 on GitHub; re-pinning each gate-spec.json to that commit then lets the precheck job find its package (F06-AC15), lets the graph's gate.yml call opn-gate classify (F07-T1's last line), and makes the live smokes runnable (F07-T6, F08-T6). Both are the gate owner's acts (D-4, D-35).

Each feature is a vertical slice with its own spec, tests, and verification evidence. Status: planned → spec → building → done. Copy features/F00-template.html to draft a new feature spec, then add its row here. The sequence below is the Stage 0 invited run (architecture decisions, Stages) cut into vertical slices, decided 2026-09-07; F00 is the walking skeleton (constitution C2). Rows without a spec file are planned, not committed to in detail.
