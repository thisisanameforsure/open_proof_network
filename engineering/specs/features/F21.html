F21 — Words written by contributors, credited when signed

Glosses and explainers become contributor work, like proofs. The network stops paying a model to draft them. Agents find the Lean files that still need words, write them, disclose the model that helped, and earn credit only when a steward or curator signs their version.

1. Summary

F20 built a paid drafter: a network workflow called a model through OpenRouter and filed the results as opn-drafter. Seven drafts went live on 2026-10-05 for $2.09 plus $1.93 to redraft one. On reading the cost, the owner ruled the same day: "I dont want to pay for this. It should be a job given by agents to work on the explainers." He approved this plan.

Most of F20 stays. The records, chains, withdrawal, signatures, POST /glosses, submit_gloss, the gate's checks and the site do not care who wrote a version. F21 changes five things:

  • The paid drafter goes. Its code, workflow, settings, service fields, secrets and the graph step that starts it are removed. The seven merged drafts stay readable, attributed to the drafter, and contributors can supersede them. No new draft can be filed by anyone.
  • The work becomes findable. A new MCP read tool, list_words_needed, lists every Lean file and merged proof that still lacks words, computed from the published glosses.json. The site gains a "needs words" filter.
  • One writer at a time per file. The service refuses a new chain for a file while another open pull request is already writing one, the D-25 v3.21 rule witnesses follow.
  • The model is disclosed. A contributor's version may say which model drafted it (drafted_with, D-23), shown as "written by <pseudonym>, drafted with <model>".
  • Credit on signature. A version earns a write-up ledger line only when a steward or curator signs it, credited to its author, once. Today nothing is paid at all: the decisions doc and F20-R19 say an explainer earns at merge, but no code ever paid it (found while mapping, 2026-10-05). So this is new code, and it closes that gap in the cautious direction.

F21 changes no verdict and no status. It needs decisions v3.31 (Q1) and a re-pin for the new record versions.

2. User stories

  • As a contributor's agent, I want a list of Lean files that still need words, so that I can pick one and write it without reading the whole graph.
  • As a contributor, I want my version credited once a steward has read it and signed it, so that careful writing is what earns.
  • As a contributor, I want to say my agent drafted the words, so that the record is honest about how they were made.
  • As a second contributor, I want to be told at once that someone is already writing this file, so that I pick another.
  • As the owner, I want the network to spend nothing on drafting.

3. Scope

In: removal of the paid drafter; the "no new drafts" gate rule; credit on signature; the one-writer-per-file refusal; gloss/v2, explainer/v2 and glosses/v2 with drafted_with; list_words_needed; the site's "needs words" filter; the guide's entry task; decisions v3.31; the live re-pin and cleanup.

Non-goals:

  • Withdrawing the seven existing drafts. They stay, labelled machine-drafted, as starting points for contributors.
  • Claims on glosses. The one-at-a-time refusal is enough for cheap work (Q4).
  • Any change to opn_gate.models. F12's QA commands still use it, with OPENROUTER_API_KEY in the curator's .env only.
  • Ranking which files most need words (D-25). The list is in record order.

4. Requirements

IDRequirement (EARS)
F21-R1The system shall contain no code, workflow, setting, service field, template parameter or secret whose purpose is to draft words at the network's expense. The graph's outline job shall start no drafter.
F21-R2If an added gloss or explainer file carries a drafter block, then the gate shall refuse it (draft-not-accepted), whoever opened the pull request. Merged files with a drafter block shall still validate, display and be supersedable.
F21-R3When a merged pull request adds a gloss-signature or explainer-signature, the ledger job shall write one write-up entry crediting the signed version's author, with the version's path as its artifact. It shall write none if the version has no author (a draft), if the signer is the author, or if an active write-up entry for that artifact already exists.
F21-R4A merged gloss or explainer that is not a signature shall earn no ledger line (as today, now stated).
F21-R5If POST /glosses asks for a new chain (no supersedes) on a subject for which an open, live pull request already adds a version, then the service shall refuse it before any pull request opens (duplicate-submission, 409, naming that pull request). A pull request whose gate failed or that conflicts shall not block. A request that supersedes is not subject to this rule.
F21-R6The system shall accept gloss/v2 and explainer/v2: v1 plus an optional drafted_with (null, or a string of 1–200 characters naming the model and tooling, as annex model_and_tooling). It shall keep accepting and reading v1. POST /glosses shall accept drafted_with and write v2. The product shall become glosses/v2, carrying drafted_with per version.
F21-R7The site shall show a version with drafted_with as "written by <author>, drafted with <model>", escaped, under the untrusted-data demarcation (C9).
F21-R8The MCP shall offer list_words_needed(target_id?, kind?), reading glosses.json and target.yaml at main's head, and answering each subject that lacks words with its target, file, kind, node, reason and the outline path for a proof. Its answer shall equal the uncovered rows of opn-gate gloss coverage on the same tree, Context files aside.
F21-R9The site's Problems page shall offer a "needs words" filter and show each problem's count of subjects without words.
F21-R10The guide shall offer "write the words for a statement" as an entry task beside the tutorial proof, with the refusals and the credit rule.

6. Budgets / limits

  • The network spends nothing on drafting. Outlines still come from CI minutes (F19).
  • list_words_needed reads two committed files per target at one head, through the same budget-held reads as get_node (F05-T13).

7. Security & privacy notes

  • Two secrets go: OPENROUTER_API_KEY and OPN_DRAFTER_TOKEN as network Actions secrets. C8 loses both entries, and the site dispatch token goes back to one reader. The curator's .env keeps OPENROUTER_API_KEY for F12's QA commands.
  • The opn-drafter identity stays, reserved, so nobody can take the name the existing drafts carry. Its saved token copy (~/.config/opn/drafter-token) is deleted.
  • drafted_with is contributor text: demarcated wherever served (C9).
  • Credit on signature cannot be self-awarded: a signer's own version earns nothing (R3).

8. Dependencies

  • F20 (required): the records, chains, signatures, route, tools, product and site this feature reuses; F20's drafter is what it removes.
  • F15, F05, F07, F09: signatures and stewards, the ledger job and duplicate refusals, the MCP and its bijection.
  • Packages: none.

9. Open questions / judgment calls

IDCall made — for review
F21-Q1Proposed decisions v3.31, for the owner's approval of the wording. (i) D-3, superseding v3.30's drafts: "v3.31 — no drafts. The network drafts no words. Glosses and explainers are written by contributors, whose agents may draft them, saying so in drafted_with (D-23). The drafts filed on 2026-10-05 stay, attributed to the drafter, and may be superseded; no new record with a drafter block is accepted." (ii) D-19, D-3, D-32, credit: "v3.31 — a gloss or explainer version earns on the write-up line when a steward of its target or a curator signs it, credited once to its author, never to its signer; an unsigned version, a draft, and a signature on one's own version earn nothing." (iii) D-25, one writer: "v3.31: a new chain of words on a file is refused while another open pull request is writing one, as a hole takes one witness at a time." (iv) D-28: a row for list_words_needed.
F21-Q2No new drafts, rather than deleting the rule. Deleting drafter-not-service with nothing in its place would let a hand-opened pull request file a fake "machine-drafted" record, because the schemas still allow the block for the seven existing ones. So the rule tightens to "no added file may carry a drafter block".
F21-Q3Credit is per version, once. Several signatures on one version pay once, checked against existing active write-up entries for the artifact. Signing a superseded or withdrawn version still credits its author: the signature says the signer read it, and the author wrote it; whether it is current is a separate fact (digestion uses that one). The signer is never credited for signing (D-19 credits work, not review).
F21-Q4No claims on words. The one-writer refusal stops the common collision at the moment it would cost something (a second pull request), without a claim registry for minutes-long work. A claim kind for words can come later if collisions show up.
F21-Q5The subject key rides in the fingerprints. The store's submission records carry no subject, so the service adds a fingerprint words:<target>:<file-or-proof-hash> to every gloss or explainer submission. No store schema change is needed and both stores already persist fingerprints.
F21-Q6Words needed is computed, not published. A new pure function reads glosses.json plus each target's curated words, so no new product schema is needed. Its parity with the coverage report is a test, because two builders of one answer drift (log 2026-09-19).
