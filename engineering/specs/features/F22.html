F22 — Words, second pass: what the first writers found

On 2026-10-06 four agents wrote the words for every Lean file of erdos-1050 and a fifth read the result as a mathematician who does not read Lean. F22 is what they found: a fork in the record, prose that rendered wrong, warnings that cried wolf, a stale guide, and the tools a writer and a reader were missing.

1. Summary

The run (graph PRs #390–#436) and its verified findings are in engineering/evidence/testers-2026-10-06/bugs.md: one P1, six P2, nine P3 and feature requests A–S. The owner's rulings of 2026-10-06: keep the latest version of the forked chain and prevent the fork; fix Markdown and make sure math renders; drop the false warnings; fix the guide; make the "withdrawn" sentence clear; make the post-merge lookup retry; fix every P3; build every feature request, with words in review shown on the page by a live fetch. Decisions v3.32 (one writer per chain head, D-3) and two D-28 notation notes carry the protocol side.

2. User stories

  • As a writer, I learn before anything opens whether my explainer's step ids resolve, what the gate will warn about and how the page will look; and I can correct an open pull request without losing my place in the queue.
  • As a writer, I can see which files someone is already writing, and which nodes are superseded.
  • As a reader who does not read Lean, I see lists, emphasis and formulas rendered, one clear sentence about withdrawn words, the proof's summary on the problem page, and a way through the reading view.
  • As the record, a chain of words never forks, and a run that merges words never goes red for a reason that is not about the words.

3. Scope

In: the service (POST /glosses, submit_gloss, list_words_needed, GET /submissions.json, the PR body), the gate (the head check, the unanchored-name warning, CONTEXT deps, outlines), the site (prose, explainer chains, the P3 items, reader features, words in review), the graph's gate.yml and merge.yml, the guide, and the repair of the forked chain on the record. Out: get_node's size, which F09-T22's session holds (T9 waits for it).

6. Budgets / limits

The post-merge retry adds at most about 30 s to a run that meets an empty answer. A dry run costs what a pre-flight costs. The page's live fetch is one GET per node page view, cached by the service as submissions.json is.

7. Security & privacy notes

Untrusted prose stays escaped before any tag; no link leaves the site from it. The CSP gains one connect-src, to the service's own origin, read from configuration. An amend is accepted only from the pull request's author, checked by token, never by name. CORS is sent on one read route only.
