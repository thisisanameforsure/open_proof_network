F04 — Site

The D-36 website: a static rendering of the graph regenerated on every merge, served from S3 through CloudFront, read-only forever, every page naming the commit it renders.

1. Summary

F04 builds site/: a generator that takes a graph checkout at a commit plus F03's products and emits static HTML; the AWS resources that serve it; and the deploy path that runs after every merge. It is the human view of exactly what an agent sees through the read tools (D-28), so it invents nothing: every page renders a file and links to it at the rendered commit. Contributor prose — explainers, annexes, postmortem detail — is escaped and shown under a fixed "unverified" or "untrusted" label with the kernel-checked object one click above it. There is no server-side code, no database, no form, no account (D-36). Cites: D-3, D-5, D-13, D-14, D-18, D-19, D-23, D-25, D-27, D-28, D-33, D-35, D-36.

2. User stories

  • As a bystander, I want to see which targets exist, what has been proved, and the frontier, without cloning anything.
  • As a mathematician deciding whether to review, I want the root statement in Lean beside the informal one and the fidelity grade, on one page.
  • As a prover, I want a node page that links the merged Proof.lean and its attestation at the exact commit.
  • As the founder, I want visitor counts from CDN logs without a tracking script.

3. Scope

In: opn_site generator with the seven D-36 pages; escaped rendering of Lean and prose; a minimal safe prose renderer (paragraphs and code fences only); client-side frontier filtering in plain JavaScript; a link checker; CloudFormation for bucket, distribution, logging with 90-day retention, OIDC deploy role; the deploy workflow in this repo, triggered by the graph repo's post-merge job; first deploy with screenshots.

Non-goals:

  • A custom domain was out of scope while none existed; one was bought on 2026-09-09 and added to the stack behind the SiteDomain parameter (Q8), which is configuration, not a change to what F04 builds.
  • Search, accounts, comments, RSS, or any input (D-36: never).
  • Markdown rendering beyond paragraphs and code fences; a fuller renderer is a later, justified dependency.
  • Contributors page content beyond what ledger files exist (F07 creates them).

6. Budgets / limits

  • Full render under 30 s for 1,000 nodes; each page under 200 KiB; frontier page paginates client-side beyond 500 rows.
  • Deploy under 5 min end to end after merge.

7. Security & privacy notes

  • All graph content is untrusted for rendering purposes (C9); escaping is the rule, allow-listing is the exception (code fences).
  • CSP: default-src 'none'; style-src 'self'; script-src 'self'; img-src 'self'; font-src 'self'; base-uri 'none'; form-action 'none' (the last two added by T28, Q30), set as a CloudFront response-headers policy (font-src added by T16, Q18: R10 is about origins, and the fonts are the site's own).
  • CDN access logs hold IP addresses: 90-day lifecycle, aggregate use only (C9). No cookies, no beacons.
  • The deploy role can write the site bucket and create invalidations, nothing else.

8. Dependencies

  • F03 (required): products. F00: attestations.
  • Packages: none new. Templates use string.Template; prose renderer and SVG layout are hand-written.
  • AWS: account with the OIDC provider; the founder bootstraps the CloudFormation stack once from the local .env credentials (C8 item 5).
