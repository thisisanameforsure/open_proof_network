Spec: `engineering/specs/features/F30.html`. Branch `f30-one-graph`. T1 landed `opn_site.one_view`
(views, layouts, `layouts_document`); T2 renders the markup below; T3 writes `static/graph.js`
against it. Both sides hold to this file; a change to it is a commit that says so.

## Keys

View keys as `one_view` makes them: `all`, `routes`, `sel`, `sel/<route>/...` (`direct`, `set:<id>`
where a family lists a leaf without a choice), `edge/<child key>` (the trunk is `edge/sel`),
`proof/<k>`. `routes` is the page's default view; a proof target still opens on `routes`.

## `svg.dag`

* Attributes: `class="dag" data-view="routes"`, `viewBox="0 0 W H" width="W" height="H"` from the
  `routes` layout. Positions in the markup are the `routes` layout's; elements not in `routes`
  carry class `off-view` (CSS: `display: none`).
* Every line of every view is present once: `<path class="edge[ use|lemma|proposed][ off-view][ touches-superseded]" data-from data-to data-key="<from>&gt;<to>" d="…">`. One element per `(from, to)` pair; `data-key` is `from + ">" + to`.
* Every statement: `<a href="<node page>"><g class="node status-<status>[ off-view]" data-node="<id>" transform="translate(x,y)" data-w="w"><title>…</title><rect class="pill" width height rx="8"/> …dot, text, halo, outline-mark… [<path class="or-mark" …/>]</g></a>`. A proved statement's `g` also carries class `proved` (R2: the filled pill, by stylesheet).
* Every junction: `<g class="junction live|dead[ off-view]" data-node="<route id>" data-route="<route id>" transform="translate(x,y)" data-w="16"><title>…</title><path class="stem"/><circle class="and-mark"/></g>` (a dead one: `dead-mark` + `dead-cross`).
* Nothing in the SVG carries `data-sets`, `data-proofs`, `on-proof`, `off-proof` or pies.

## `svg.selector`

* `<svg class="selector" viewBox…>`; laid out by `dag.layout` with the top at the top.
* Nodes: `<a href="#"><g class="sel-node kind-root|kind-node|kind-leaf|kind-proof" data-view="<key>" data-sets="<set ids, space-separated>" role="button" tabindex="0" aria-pressed="false" transform="translate(x,y)"><title>…</title><rect …/><text>…</text></g></a>`. `kind-root` is the root statement drawn above the top split when the top split is not the root; its `data-view` is `sel`'s? No: the root node has `data-view="routes"`-less — it carries **no** `data-view` and is not selectable; only its edge down (`edge/sel`) is. The top split node carries `data-view="sel"`.
* Edges: `<path class="sel-edge" data-view="edge/<child key>" data-sets="…" data-from="<parent key>" data-to="<child key>" tabindex="0" role="button" aria-pressed="false" d="…"><title>…</title></path>`. The trunk edge has `data-from="root"`. (Changed at T4: the route's approach is the child pill's second line, `text.sel-head` + `text.sel-approach`, not an edge label; edge labels piled up at a fork.)
* Proof leaves: `g.sel-node.kind-proof` with `data-view="proof/<k>"`, `data-sets=""`, hanging from the top node (or from the root node when there is one).

## `#graph-layouts`

`one_view.layouts_document`: `{ "<key>": { "w", "h", "group_y", "nodes": { "<id>": [x, y, w] }, "lines": [[from, to, kind, [[x, y], …]], …] } }`. A line's points are its bend points bottom first (`dag.Edge.points`); the curve between consecutive points with different x is the cubic `dag._curve` makes: control points `(a.x, mid)`, `(b.x, mid)` with `mid = (a.y + b.y) / 2`; equal x is a straight segment. The script draws a path the same way (`M … C … V …`), so a view's static `d` and the script's agree.

## `graph.js` (T3)

* State: `{node, view, hover}`; hash `#node=<id>&view=<key>` (`view` omitted when `routes`).
* Pill click: select the panel (as `problem.js`), never the view. Pill hover/focus: light its lines and neighbours (`lit` classes, `hovering` on the svg), nothing moves.
* Selector node/edge click: `transition(view)`; clicking the selected one again, or Escape: `transition("routes")`. Table row click: its `data-view`. `aria-pressed` on the chosen element; table rows outside the view's `data-sets` hidden, count line "showing n of m".
* Selector hover/focus, table-row hover: `preview(view)` = add `lit` to every node/edge in `layouts[view]` and `picking` to the svg; no coordinate changes; leave restores.
* `transition(to)`: phase 1 fade out elements not in `to` (opacity → 0, 200 ms, then `off-view`); phase 2 (400 ms, requestAnimationFrame) interpolate each shared node's translate and each shared line's points (resampled to a common count) and the svg's size/viewBox; phase 3 remove `off-view` from the new elements and fade in (200 ms). `prefers-reduced-motion: reduce` → one step. Sets `data-view` on the svg at the end. Phase 2 writes the final `d` from the layout's points via the same path builder.
* View-toggle: `all` ↔ `routes` through `transition`; pressed state; while a selector view is selected the toggle reads unpressed and clears the selection.
* Superseded toggle: as today (class `hide-superseded`).
