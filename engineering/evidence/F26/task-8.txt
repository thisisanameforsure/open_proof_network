== Part 1: step 9 (R12, AC9) ==

Where step 9 decides: gate/opn_gate/modes.py `with_statement_review`, called once, by
`opn-gate classify` (cli.run_classify), before any sandbox. Order after this task:

  alternate                         -> alternate_basis (unchanged)
  not a proof/partial               -> unchanged
  step9_not_asked (intermediate,    -> recorded, and the review is NOT read (AC9 c)
    calibration)
  review_step.standing(target) None -> without_review: certificate, else evidence, else a
                                       person — today's rule exactly (F26-Q7)
  review_step.standing(target) set  -> with_review:
       standing.satisfies           -> kind `certificate`, reference
                                       review:review/review.yaml@<root hash>:<grade>
       step9_evidence >= minimum    -> kind `provenance`, the evidence reference (v3.15, unchanged)
       neither                      -> review_held: Diagnostic `review-incomplete` (step 9), which
                                       modes.check reports, so classify exits 1 before any sandbox

Each basis is one named function (root_certificate, step9_evidence, review_step.standing), and
the no-review path is its own function (without_review), so reversing v3.39 is a deletion of the
`if review_standing is not None` branch. `review_state` (the words) is a new key of the
classification JSON, null when no review was read.

The product mirrors the rule: products.step9_basis (targets-index `step9`) reads the review too —
`certificate` when the review is complete at screened-and-signed, `evidence` when catalog evidence
stands in, `review` otherwise; no review, unchanged. No schema change (the enum already has the four).
