  opn_gate.review.latest_of(named: Iterable[tuple[str, dict[str, Any]]]) -> list[dict[str, Any]]
      The pair records in force, one per (a, b), sorted by (a, b), from (file name, record) pairs
      in any order. Pure: no disk, so the service can call it on what it read through the host.
  opn_gate.review.latest_pairs(base: Path) -> list[dict[str, Any]]
      The same over a target's review/ directory on disk (reads base / "pairs").
  opn_gate.review.in_order(named) -> list[dict]       every record, oldest first
  opn_gate.review.generation(name: str) -> int        k from <a>--<b>--<date>-<k>.yaml, else 1

The rule (in_order): a record's place is (date, generation read from the file name, file name);
the last of a pair in that order is in force. Nothing is renamed and every published name keeps a
place (D-34): <a>--<b>.yaml is generation 1, the job's later records are --<date>-<k>.yaml with
k >= 2, so on one day the first record is oldest and -10 is newer than -2. review._pairs (derive,
open_pairs, split_variants) and the job's _load (review_pairs.latest) both go through it.

Fix (review_pairs):
  contributed(job, a, b, direction, budget) — the records for the direction whose
    statement_hashes equal the candidate records' statement_hash, by record date then file
    name; the first whose re-check passes settles it (_settled: add_exhibit kind pair, candidate
    = the direction's first claim, test = its second — the job's own convention, so for
    `backward` the exhibit's candidate is b — key `contributed:<record stem>`, result proved or
    refuted, the record's Lean as the exhibit's Lean, detail naming the author, the direction
    and the record), state with exhibit set and attempt null. Later records are noted "not
    needed". When none passes: open, attempt {who: the record's author, tool: "pair-proof
    <stem>: re-check failed: <why>" (cut to pair/v1's 200), budget_s}, every failure noted.
  recheck(job, rec, first, second) — template at the record's kind and case (ValueError is a
    refusal), split, problems, verdict(), and for a proof the guarded copy must NOT elaborate.
  verdict(job, lean) — THE SEAM for agent G's shared verdict: today Runner.check (no error, no
    sorry). Axioms are not judged yet; wire G's function here when the lead says it landed.
  resolve(...) notes a record for a direction already settled ("not needed") without
    re-checking it; run_pairs notes every record no surviving pair looked at ("not a direction
    between two surviving candidates; not read").

Decisions:
  - "Several records: take the first by record date then name." Read as: the first whose
    re-check passes. Taking the first outright would let one failed record block a good later
    one forever (the failed attempt is stable across runs). Tested both ways
    (test_of_several_passing_records..., test_a_failing_first_record_does_not_block...).
  - The job re-checks against the template it computes itself from the candidates, not only by
    elaborating: without that a file could prove some other theorem and pass.
  - A failed re-check is re-done on every run (the runner's cache is per run); the result is the
    same document, so nothing is written (tested). It costs two elaborations per run per failed
    record until a passing record or the job's own proof settles the direction.
  - Hash source: the candidate record's statement_hash field, as pair-proof/v1's description
    says; the job does not recompute it from the Lean.
