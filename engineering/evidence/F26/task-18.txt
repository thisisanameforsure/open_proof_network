== Proposed Q entries (for the lead; spec HTML not edited) ==

Q-a (supersession, T18). A pair's later records are named <a>--<b>--<date>-<k>.yaml and sort
  before <a>--<b>.yaml by name, -10 before -2; a same-date tie went by file order, so the older
  record won on reload and in review.derive. The rule is now (date, generation k read from the
  name, 1 for the first record, then the name), in review.in_order / latest_of / latest_pairs,
  called by derive, open_pairs, split_variants and the job's own reload; the service's listings
  are to call latest_of (T19). No record was renamed (D-34) and the writer's names are unchanged,
  so the rule is the only change; a writer naming its records by (date, zero-padded k) would make
  file order agree too, but every existing reader would still need the rule for the names
  already published.

Q-b (several records for one direction, T18). The brief's "take the first by record date then
  name" is built as "the first, by record date then name, whose re-check passes": taking the
  first outright lets one failing record block every later good one, because a failed re-check
  is stable from run to run. Every record not used is named in the run's notes.

Q-c (the ledger's artifact, T18). ledger/v2's `artifact` says "relative to the node directory".
  A pair-proof record lives under the target, not a node, so the entry's artifact is the
  record's path relative to the target directory (review/pair-proofs/<name>), the registration
  line's precedent (F25-T4), and its `node` is the target's root. Read as: relative to the
  directory the line's record lives in; the schema's description could say so at its next bump,
  with no change to any entry.

Q-d (credit at merge, T18). The review line is written when the record merges, from the record,
  like every other merged artifact; the job's post-merge re-check does not gate it. A record the
  gate admitted and the job then refuses (it should not happen: the same verdict, F26-T17) keeps
  its line until a curator's credit correction (F07-T66). The identity is the record's author,
  not proposer_of (the service acts for the author it writes, F18-Q7); holding a hand-opened
  record's author to its opener is the gate's pre-merge check (T17). An empty `models` (a
  person's work, v3.31) is tooling `undeclared`, statement_tooling's convention.

Q-e (a refutation's question, T18). A contributed refutation raises its disagreement question
  like the job's own, through the exhibit's header, but only for a case no test is on record
  for: an instance n < 4 already has an agreement test from both survivors (AGREEMENT_N), so it
  raises none. That is the job's rule for its own refutations too; a contributed refutation at
  such an n contradicts an agreement test, which the job does not reconcile today.
