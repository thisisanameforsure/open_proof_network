Where the time goes (not measured locally; for the owner's cost call, Q36/T28)
  Per gate run, for every proof, alternate and partial, step 4 now adds:
    1. defs.compile_all into work/meaning: one `lean` per target definition (Mathlib targets'
       defs import Mathlib: each is a Mathlib import, roughly the cost of elaborating a
       Mathlib-importing file header, seconds to tens of seconds and ~1-3 GiB resident).
    2. `lean` on the node's repo Context.lean (imports the target defs / Mathlib): one import.
    3. `lean` on Statement.lean: one import.
    4. opn-statement-meaning: imports the artifact's module, which on a Mathlib target is a
       Mathlib-sized environment (one import, read from oleans, no elaboration).
  So: two extra Mathlib imports for the statement side, one for the comparison, plus one per
  target definition. Each is a separate process (and container), so peak memory is one import's,
  not their sum (the F02-T7 lesson). Each call is under the step's wall-clock cap.
  Mitigation if it bites: the statement-side build is a function of the admitted files only
  (target defs + node Context + Statement), so it is cacheable under the olean cache's key.

Proposed Q entry (F08-Q41)
  F08-Q41 The meaning guard reads every artifact that claims the statement (T28; 2026-10-04;
  audit finding A). Q36 held the road through a dependency's merged proof with no use line
  anywhere as a strict xfail, and Q40 left it for the owner's call on cost. Decided by the
  owner's ruling on the audit: no new rule about what a Proof.lean may contain; the verdict must
  not depend on it. So R17's comparison runs for every artifact that declares the statement's own
  theorem: a proof, an alternate and a partial's assembly, read from the staged file
  (meaning.claims_statement). For a plain proof this is the first type comparison at all:
  artifact.judge passes a proof on its text, so until T28 the verdict that a proof proves its
  statement rested on the text being repeated, never on what it elaborated to. Cost: one more
  build of the target's definitions, the node's Context and its Statement, and one import of the
  artifact's environment, per gate run. Not covered: a counterexample's ¬S and a vacuity
  certificate's ¬W are still compared by opn-artifact-type in the artifact's own (larger)
  environment, which elaborates contributor source; proposed T29b below. Reversal: claims_statement
  returns False and the guard is T25's.
