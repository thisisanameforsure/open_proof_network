F08-T38 — the gate refuses a disputed record that names no standing claim (D-18 v3.28)
Branch audit-s-followups, 2026-10-04. Follow-up named in F08-T35's evidence.

Finding: curator mode admitted any schema-valid node-status/v1 record, so a hand-written
`disputed` record with no `reference` (or one naming a missing, withdrawn, foreign or free-text
claim) passed the gate. It took the node off the frontier and could never lift when a claim was
withdrawn (graph.disputed_is_void needs the reference, F08-T32). F08-T35 held only the curator
command to D-18 v3.28's rule.

Change:
- modes.check_status_record: outside proposal mode, a node-status record goes to
  modes.check_dispute_reference, which calls curator.accepted_claim — the command's own rule
  (CLAIM_REF_RE, records.defect_claims, withdrawn claims refused) — and turns its CuratorError
  into the new diagnostic `dispute-claim-unnamed`. Any other status (abandoned, D-14) is not
  asked. curator is imported locally (it pulls in the toolchain steps).
- codes.py: the `dispute-claim-unnamed` row (gate, no step).
- No schema change, no new mode, no api change. The live graph carries no disputed record
  (git grep 'status: disputed' over targets/*/nodes/*/status at the sibling's origin/main: none),
  so the rule refuses nothing already merged.

F08-Q49 — The gate holds a disputed record to the command's rule (T38; D-18 v3.28). A `disputed`
node-status record in a curator pull request must name, in `reference`, a valid defect claim on
its own node that is on the record and not withdrawn — `defects/<file>` or the claim's path from
the graph root — or step 2 refuses it with `dispute-claim-unnamed`. The check is
curator.accepted_claim, the function `opn-gate curator status <node> disputed` already runs
(F08-T35), so a hand-written record and the command's agree by construction; the claim must
already be on main, since a defect claim is not a curator-mode file. `abandoned` takes no claim
and is unaffected; a target's status records are unaffected. Reversal: drop the node-status branch
in check_status_record and the code row.
