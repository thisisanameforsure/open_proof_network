F08-T8 — one theorem name per target: the declaration check (Q20).
2026-09-12

THE DEFECT
----------
Q18 held it as a strict xfail against the real toolchain: two nodes of a target could declare the
same theorem, because each Statement.lean elaborates as its own module and Lean has no complaint.
The clash surfaced only in the Context.lean of the first node to depend on both (F01-R6) — the
wrong node and the wrong person, since the node that fails is the one that did nothing wrong.

THE FIX
-------
admit.DeclarationCheck, second in R1's order, straight after layout: compares the proposal's
declaration with every sibling Statement.lean of the target and refuses `declaration-clash`,
naming the node that holds the name. It exempts exactly the node named in `supersedes` — restating
the theorem is what a revision *is* (D-8, F08-R9) — and no other; a sibling whose own statement is
malformed declares nothing and cannot be collided with.

Q18's reason for holding it ("no fake can see a name clash") applied to the old framing, not to
the fix: the check is a string comparison over files already on disk, so the fast tier covers it
after all, and the lean-tier test that was the xfail is now an ordinary test.

Every read is a Python read of the host tree, never a path handed to the toolchain, so the
sandbox's mounts (F08-Q13) are not in play.
