Change:
- graph/v5 (new; v4 is live on the graph so not edited, D-34): each node row carries
  `defect_claims`: [{file: defects/<file>, class, state: standing|withdrawn, accepted: bool}],
  oldest first; `accepted` is true for the claim the node's standing `disputed` record names
  (D-18 v3.28, F08-T35). Files that do not validate are logged and passed over.
- context/v3 (new): CONTEXT.json carries the same list. One function, context.defect_claims, builds
  it through a Reader; products.graph_doc calls it with a DiskReader, the bundle (post-merge job and
  the api's derived bundle over the host, F10-Q7) with its reader, so the lists cannot disagree.
  context._latest_status now serves successor_of and the accepted check.
- HASHES appended (graph/v5, context/v3); test_schemas list; goldens regenerated (info.json schema
  index gains graph 5 and context 3; graph.json rows and CONTEXT.json gain `defect_claims: []`;
  nothing else moved). Site goldens unchanged.
- Version sweep: products.GRAPH_SCHEMA, context.SCHEMA/ACCEPTED, site model PRODUCT_SCHEMAS
  (graph/v5), MCP get_node result schema enum (context/v3), api-deploy package check
  (context/v1..v3), tests pinning versions restated (test_node_proofs, test_products,
  test_finding_circular_below_context, api test_finding_context_window). The api reads graph.json
  without pinning a version; get_target's schema pattern accepts any graph/vN.
- Site: the node page shows each standing claim — class, "claim open", the file linked at the
  rendered commit through file_link (no hostname in the template) — and "disputed" beside the one
  a curator accepted. Withdrawn claims are not shown on the page (graph.json still lists them). A
  node with no open claim renders exactly as before ($defects is empty).
