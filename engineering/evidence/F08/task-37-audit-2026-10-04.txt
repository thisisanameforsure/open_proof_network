== The reading (judgment calls)
- A declaration runs from `theorem`/`lemma` to the first `:=` outside brackets that is not a
  let/have/letI/haveI binding's, and that `:=` must be followed by `sorry` or `by sorry`. So a
  Context's signature must be sorry-bodied too; a proved theorem in a Context is refused.
- Attributes (`@[...]`) and modifiers (`protected`, `private`, `noncomputable`) are refused,
  including `@[...]` inside a type. The live record has none; no gate writer emits one (the wave
  driver drops the registry's `@[category ...]`).
- `section` and `universe`/`variable` are refused: D-3 v3.28 lists namespace and end only.
- An `open` line holds names and `scoped`/`hiding`/`renaming`/`in`, parentheses and arrows; an
  `open ... in` line before the theorem is allowed. A multi-line `open` (names continued on the
  next line) would be refused; nothing on the record does it.
- Inside a type, Mathlib's `#s` card notation is allowed (only command words and attributes are
  refused there): a command can follow a declaration only after its `:= sorry`, so one inside a
  type is a parse error, which admission refuses for not elaborating.
- strip_comments (used elsewhere) reads `'"'` as the start of a string; code_mask does not, so a
  command cannot hide from this scan behind a quote Lean reads as a character (tested).

== Proposed Q entry (F08-Q48)
F08-Q48 (T37, D-3 v3.28). What a statement may hold is read as a sequence of commands over the
text with comments, strings, characters and «» names masked: header lines (`import`, `open`,
`namespace`, `end`) run to the end of their line and hold names only; a declaration is `theorem`
or `lemma` up to its body, the first `:=` outside brackets that is not a let or have binding's,
which must be `sorry` or `by sorry`. Anything else where a command starts is refused as
`statement-command-forbidden`, naming the file, the line and the command. Attributes and
modifiers are refused (none on the record; none written by any gate writer), and so are
`section`, `universe` and `variable`, which D-3 does not list. The rule runs at admission's layout
check and at a submission's step 2, before anything is built; the service refuses a proposal by
the same function before any pull request opens. Every committed statement and context on the
graph met it when it landed (114 and 114 at 6d1b2bf8; 151 distinct blobs in its history). A
Mathlib command word inside a type is refused too, though a command can only follow a
declaration after its `:= sorry`; that list is belt and braces, not the guarantee.
Not covered: targets/<id>/formalizations/<name>/Statement.lean (F14-R7) is not a node file and is
not read by this rule; if the judges import those too, the same function applies (follow-up).
