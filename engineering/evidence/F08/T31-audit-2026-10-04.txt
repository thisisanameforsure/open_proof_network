What changed

  `withdraws` is `status/<file>` or `defects/<file>`, relative to the withdrawal's own node.
- paths: role `withdrawal` at targets/<t>/nodes/<n>/withdrawals/<stamp>-<curator>.yaml, a CURATOR_ROLE
  (so F08-R8's curator mode: a listed login, reviewed by the other listed identities), append-only
  like every curator record. layout tolerates the directory.
- modes.check_withdrawal: validates, and refuses `withdrawal-unknown-record` when the named file is not
  a valid status record or defect claim of the same node in the checkout. codes.py has the row.
- records: `withdrawn(node_dir)`; `load_node_status` reads a withdrawn status record as absent (the
  latest of the rest is the override), `circular_claims` passes over a withdrawn claim. Every reader
  that goes through these — graph.load_target, current_id, modes, uses, steps/artifact, the site
  model — therefore reads it as absent. A withdrawal that does not validate is passed over, so the
  record it names stands. No date is compared anywhere.
- info.json goldens: the schema index gains `withdrawal: [1]`; test_schemas' published set likewise.

Why the path is under the node (justification)
- Status records (status/) and defect claims (defects/) are node-scoped already; a withdrawal filed
  beside them is found by every reader that already takes a node directory, with no new walk.
- The record is named relative to the node and the schema's pattern admits only status/ or defects/,
  so a record of another node or another target cannot be named at all (no cross-target check needed;
  the one-target rule of classify stays the only scope rule).
- Not covered, deliberately: target-level status records (targets/<t>/status/, the root declaration)
  and defs/defects/ claims. Nothing derives a node status or frontier entry from a defs/ claim, and a
  target declaration is superseded by a later declaration already.

Proposed Q entry
  F08-Q43 (T31; D-14, D-18 v3.27). Where a withdrawal lives and what it may name. A withdrawal is
  `nodes/<n>/withdrawals/<stamp>-<curator>.yaml` (withdrawal/v1) and names `status/<file>` or
  `defects/<file>` of its own node, so every reader that takes a node directory finds it without a
  new walk and nothing on another node or target can be named. It is a curator record (F08-R8:
  listed author, the other curators review). A withdrawn record stays in the tree and is read as
  absent: the latest of the remaining status records is the override, whatever its date. No date is
  compared; a withdrawal applies because it is on the record (2026-09-19, ancestry not dates).
  Target-level declarations and `defs/defects/` claims are not withdrawable: a later declaration
  already supersedes the first, and nothing is derived from a defs/ claim. A malformed withdrawal is
  passed over, so the record it names stands. Reversal: one commit's revert of the withdrawal
  restores the products byte for byte (tested).
