==================================================================================================

Part 1: the context bundle (gate/opn_gate/context.py)

What changed
- context._withdrawn_names(reader, target, node, directory): records.withdrawn_names through the
  bundle's Reader — lists <node>/withdrawals/, validates each file as withdrawal/v1, passes over one
  that does not (logged), returns the names under status/ or defects/ it names. No date compared.
- _circular_claims skips a withdrawn defects/ file; _current_id.successor_of skips a withdrawn
  status/ file before latest_status picks the override. Both builders (the post-merge job's
  DiskReader and the service's HostReader, F10-Q7) go through these, so the fix reaches both.

Note on "parity". Both CONTEXT.json builders already share context.build, so their bytes agreed
with each other before the fix (the HostLike equality test passes before and after). The
disagreement was between the bundle and the gate's own graph facts (graph.load_target, which the
site's ancestor note and the frontier render): records.circular_claims / load_node_status read
withdrawals, the bundle's reader did not. The red tests take graph.load_target as the oracle for
every node's circular_below.
