Part 1: the context bundle (gate/opn_gate/context.py)

What changed
- context._withdrawn_names(reader, target, node, directory): records.withdrawn_names through the
  bundle's Reader — lists <node>/withdrawals/, validates each file as withdrawal/v1, passes over one
  that does not (logged), returns the names under status/ or defects/ it names. No date compared.
- _circular_claims skips a withdrawn defects/ file; _current_id.successor_of skips a withdrawn
  status/ file before latest_status picks the override. Both builders (the post-merge job's
  DiskReader and the service's HostReader, F10-Q7) go through these, so the fix reaches both.

Note on "parity". Both CONTEXT.json builders already share context.build, so their bytes agreed
with each other before the fix (the HostLike equality test passes before and after). The
disagreement was between the bundle and the gate's own graph facts (graph.load_target, which the
site's ancestor note and the frontier render): records.circular_claims / load_node_status read
withdrawals, the bundle's reader did not. The red tests take graph.load_target as the oracle for
every node's circular_below.

Part 2: the precheck refusal's replacement (api/opn_api/precheck.py, replacement_of)

What changed
- context._withdrawn_names is now public, context.withdrawn_names (one rule for both readers).
- precheck.replacement_of lists the node's withdrawals through a small Reader over the graph at
  main (_GraphAtMain: frontier.committed + githost.list_dir) and skips a withdrawn status record
  before taking the newest superseded one. Still best effort: a host error on the withdrawal
  listing yields None, as any other host error there does. The record-picking rule (newest by
  file name, superseded only) is otherwise unchanged; it is not the gate's latest_status
  (date, then name, any status) and was not asked to become it.

Proposed Q entry
  F08-Q45 (T33; D-18 v3.27, F10-Q7). Every reader of a node's records reads withdrawals, including
  the two that do not read a directory: the context bundle's Reader (which the service's
  toolchain-free builder shares, so the two bundles agree byte for byte) and the precheck's
  replacement_of. Both use context.withdrawn_names, which applies records.withdrawn's rule over a
  reader: a withdrawal that does not validate is passed over, no date is compared. The oracle for
  the bundle's circular_below is the gate's own facts (graph.load_target), which the site's
  ancestor note and the frontier render. A reader added later that reads status/ or defects/ under
  a node goes through records (a directory) or context.withdrawn_names (a reader), never neither.
