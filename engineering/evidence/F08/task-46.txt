--- the fix ----------------------------------------------------------------------------------------

curator.revise(relation=, relation_proof=): a label not in RELATION_LABELS, a label needing proof
without one, or a proof without a label are CuratorError before any record is built (nothing on
disk, tested); with a label the proposal is origin "variant" with that label and proof (the
scaffold writes the `-- relation:` line, F08-Q6); without one, the old node's origin, relation
and Relation.lean, as before. cli: `--relation {related,partial,resolves,refutes}` and
`--relation-proof <file>` on `revise`, read before any work (_read_flag_file).

graph: PartialRecord.holder (the node whose directory holds the file; its own id except for an
inherited partial); statement_identity(text, node_id) — the statement's text with its own
Context import made id-free, hashed, because statement_hash can never agree across a revision
(the import names `<node>-v<n>`); load_nodes folds, for every node whose `supersedes` chain
keeps the same identity, the superseded nodes' own partials (before its own) and holes (after
its own), reading a snapshot of each node's *own* records so the fold is order-independent
(the first draft read the folded value and a revision of a revision got the partial twice —
caught by test_inheritance_follows_the_supersedes_chain); is_hole_child reads the same chain
from the tree (same_statement_chain), so staging (F07-R22), the post-merge reuse rule and the
lemma backfill see an inherited hole as the revision's. products.decompositions_of resolves
a partial's file, annex and gloss against its holder; outline_graph lists a partial under its
holder only; lemma_backfill.candidates takes a node's own partials only. blocked_because
needed no change: it already sets `node.holes` aside, and the revision's holes now include
the inherited ones.

Two test slips of mine on the way, both fixture facts: the fixture root carries a Proof.lean,
so the partial's passing attestation read as its proof (F03-Q7 reads both together) — the
decomposed fixture unlinks it, which is the live crux's shape; and a second `revise` in one
test at the same DATE collided with the root's stale record (append-only: the refusal was
right). The CLI refusal's key is `refused`, not `error` (read from cli._refused).

Why lemma_backfill.py and outline_graph.py changed: load_nodes now folds an inherited partial
into the revision's `partials`, so without a holder filter the same file would be listed twice:
once under the superseded node that holds it, and once under the revision. The backfill would
then propose a lemma edge for each, and the outline graph would draw each. Both now take a
partial only under its holder (`holder in ("", n)`; an empty holder is a record built before
the field existed).
