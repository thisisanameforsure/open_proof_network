F07-T62 — merge actor robustness, and every graph action pinned to a commit (audit 2026-10-04)
==============================================================================================

Graph branch: audit-b-workflows, commit f568f6a06 (merge.yml pick.py; gate.yml uses: pins). Not pushed.

Findings and fixes (pick.py in merge.yml):
1. Open pull requests were read as one page (per_page=100) and the host lists newest first, so with
   101 open the oldest — first in the queue — was never seen. open_pulls() reads every page,
   sort=created&direction=asc, up to MAX_PULL_PAGES=10 (then a warning; the newest wait).
2. An up-to-date pull request whose gate check never started (no gate check run) held its lane for
   ever: HOLD_S was measured from gate_started(), which was None. gate_started(runs, updated) falls
   back to the pull request's updated_at, in decide() and in more_appends()/holds_the_line(), so the
   hold ends HOLD_S after the host last changed it. A gate that has not started yet still holds.
3. An empty-diff service pull request got lane None (`lane_of_paths(files) if files else None`, and
   lane_of_paths([]) was None), and a pull request in no lane closes every lane when it is first.
   lane_of_paths([]) is now EMPTY_LANE ("", a lane of its own) and the caller distinguishes [] from
   None (unreadable). policy.json and multi-target pull requests still close every lane.
Plus: every `uses:` in gate.yml (and render.yml, from T60) is a full commit SHA with `# vX`:
