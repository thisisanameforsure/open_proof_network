THE RULE
  A target is two sub-lanes. An append/ branch whose every path is a word or a report T81 leaves
  inert (`inert_role`) is in the target's append sub-lane, keyed (target, "appends"). Everything
  else in the target, building pull requests and the appends a building verdict can read (annex,
  review records, shelving, status, withdrawals, revisions, defects, stewards, ...), is in the
  building sub-lane, keyed by the target as every lane was. A building pull request that holds,
  updates or merges closes only the building sub-lane; a batch closes only its own sub-lane, and
  `more_appends` walks only it, so a words batch no longer ends at a building pull request. A pull
  request in no lane (lane None) still waits until it is first and closes every sub-lane;
  EMPTY_LANE stays its own (an empty diff is never words). Kept: F22-T22's words_moved update
  (closes the append sub-lane only), MAX_BATCH across the run, T32's unknown-mergeability holds,
  T46's stale heads. The run computes `inert_of` from the pull request's file list (the host's
  facts only; an empty or unreadable list is not words).

SOUNDNESS (checked, not assumed)
  - Appends already merged behind main without a re-gate (T45). Unchanged: a building merge in the
    same run as a words batch is the same pairing as the two in consecutive runs before.
  - A building pull request merges behind main only when nothing that can change its verdict
    moved. A words append merged past a holding or updating building pull request moves only
    paths T81 found no building verdict reads, so the building pull request stays up to date and
    its running gate is gated against everything its verdict can see.
  - An append that a building verdict can read stays in the building sub-lane. Had every append
    gone in the sub-lane, a shelving merged past a holding proof could change that proof's verdict
    (shelved_refusal reads it through load_target), and an annex could flip a holding skeleton
    from red to green. Neither would have produced a false merge (the proof would read behind and
    be updated, as any stale one is), but each would restart the gate T31 exists to protect, so
    they are excluded by construction rather than caught after.
  - The post-merge job re-checks every merge commit and attests nothing that fails: the backstop.
