Fix
---
* api/opn_api/config.py: `open_appends_per_identity`, env `OPN_API_OPEN_APPENDS_PER_IDENTITY`,
  default `DEFAULT_OPEN_PRS_PER_IDENTITY` (10); published in `rate_limit_policy` (info.json) as
  `open_appends_per_identity`, beside the two existing caps. The global cap is unchanged.
* api/opn_api/submissions.py: `check_open_caps(ctx, identity, branch)` (called from `open_pr`,
  which knows the branch). The new pull request's half is `pending.branch_sub_lane(branch)`; the
  caller's open records are counted in that half only, classified by the one helper the queue uses
  (`pending.sub_lane`: the cached open listing's head_ref, else the record's kind; no host read
  of its own). Appends against `open_appends_per_identity`, building pull requests against the
  existing `open_prs_per_identity`. The refusal keeps the code `open-pull-requests-cap` and names
  which cap: the message says "appends open ... the cap for appends is N
  (open_appends_per_identity)" or "building pull requests open ... (open_pull_requests_per_identity)",
  and `details` carries `cap_name` and `half` beside `cap` and `open`.
* gate/agents/AGENTS.md: the caps paragraph describes the two halves and the three published caps.
