2. The change (api/opn_api/submissions.py; check_placement extended, no parallel check)
---------------------------------------------------------------------------------------
check_placement gains artifact_type and calls check_artifact_path first, so every refusal about
where a file lands stays in one function, before the precheck is bound or anything pushed.
check_artifact_path reads each bundle path's role from the gate itself (opn_gate.paths.locate):
  PARTIAL_TYPES = (partial, reduction)   must carry a role-"partial" file and no role-"proof" file.
                                         That is the gate's partial mode (modes._mode_for: the
                                         assembly plus appends). A reduction is a one-hole partial
                                         (steps/artifact.py is_reduction), so it lands the same way.
  PROOF_TYPES   = (proof, counterexample, vacuity)   must carry no role-"partial" file. The
                                         certificate is Proof.lean (paths Role "proof", D-3); an
                                         alternate (role "alternate") is not a partial, so the D-25
                                         rules below it are untouched.
Refusal: 400 artifact-path-mismatch, naming the path the type belongs at, e.g.
  "a partial is an assembly at targets/propositional/nodes/tutorial-and-swap/attempts/<ts>-<pseudonym>-partial.lean
   (D-12, F11-Q28), not targets/.../Proof.lean; a proof of the node is targets/.../Proof.lean with
   artifact_type proof"
The suffix is postmerge.PARTIAL_SUFFIX, imported rather than restated; postmerge's imports are
stdlib plus opn_gate.attestation/schemas/signer, which precheck.py already imports in the api.

Not made stricter than the gate: two assembly files, or an assembly plus appends, stay accepted
(the pin above), because the gate's partial mode takes a set of roles, not a count.
