F07-T63 — the submitter the attestation records is the one the gate saw (audit 2026-10-04)
=========================================================================================

Graph branch: audit-b-workflows, commit ff3363c0d (gate.yml: two gate-job steps, the post-merge body step).
Not pushed.

Finding. The post-merge job fetched the pull request's body after the merge (gh api pulls/N --jq
.body) and passed it to the pinned gate's postmerge command as the submission block (F07-T14:
submitter, declared model and tooling, consumed precheck). An edit after green was recorded although
the gate never saw it.

Fix.
- gate job, when run=true: "Keep the pull request's body as this run saw it" writes
  github.event.pull_request.body (via env PR_BODY, never interpolated) to a file, and an
  upload-artifact step (SHA-pinned, v4.6.2) keeps it as submission-<number>-<head.sha>,
  overwrite: true for a re-run of the same job.
- postmerge body step: reads the merged PR's head.sha, lists artifacts by that name, takes the newest
  unexpired one's workflow run and `gh run download <run> --name <name>`; with none, records the
  live body and prints ::warning::. The job's existing actions: write covers the artifact reads.
- No gate CLI flag is added: inert on the current pin (3422bb4).

Red tests (run against the job as it stood):
  test_finding_postmerge_submission.py::test_the_recorded_body_is_the_one_the_gate_saw
      pr-body.md held "submitter: someone-else" (the live edit), not "submitter: honest-prover"
  ::test_the_newest_gate_run_on_that_head_is_the_one_read            same
  ::test_with_no_body_kept_the_live_one_is_recorded_with_a_warning    no ::warning:: (silent)
  ::test_the_gate_job_keeps_the_body_from_its_event_named_for_its_head  no such steps

Not verifiable locally: the real host's artifact listing and `gh run download` (a fake host here).
The first merge after this lands on the graph shows "as the gate saw it at <sha>" in the post-merge
log; merges gated before it print the warning, as designed, until their artifacts are gone.

Proposed Q entry (F07-Q67): "The submission block is the body the gate saw: the gate job keeps its
event's body as the artifact submission-<pr>-<head sha>, and the post-merge job reads the newest
unexpired one for the merged head. The live body is a fallback with a warning (pre-change merges,
expired artifacts), so the default artifact retention bounds how late a replay keeps the gate's view."
