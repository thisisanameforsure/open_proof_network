TWO SCHEMAS
-----------
  ledger/v1        D-19's six lines as an enum, of which F07 writes two. No weight, no score and
                   no total anywhere — significance is retrospective (D-19, D-32), and a number
                   here would be the prospective difficulty scalar D-25 refuses. `status` exists
                   because credit is revocable (D-18): revoking flips it and keeps the entry.
  attestation/v4   `submitter` and `model_and_tooling`, from the opn-submission block (R13). The

                   and is recorded because a corpus is only labelled if the field is there (D-34).

The two accepted-version lists were duplicated; there is now one, in `bounce`, because
`attestation` imports that module and not the other way round.

WHAT THE DECISION SETTLED THAT THE CODE HAD WRONG
--------------------------------------------------
`contributions()` filtered revoked entries out, while D-18 revokes credit by *marking* it and the
contributors page's own text promises "revoked entries stay listed as revoked". The test written
against the page caught the contradiction. Revoked entries are returned and labelled.

A CI-ONLY FAILURE, FIXED HERE
-----------------------------
The repository's CI went red on the pushed commit while both tiers were green locally:

  api/tests/test_frontier.py::test_committed_file_is_cached_and_revalidated
  assert 1 == 2

The test forced a cached file to look stale by setting its epoch to `0.0`. On Linux
`time.monotonic()` counts from boot, so "0.0 seconds ago" is only stale on a machine that has
been up longer than the 60-second window. This laptop reads 5280; a fresh hosted runner reads
seconds, so the cache stayed fresh and never revalidated. The helper now subtracts the window
from *now*, which is true whatever the clock's origin.
