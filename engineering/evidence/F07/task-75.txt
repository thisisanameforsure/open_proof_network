F07-T75 (proposed): a hole's node is born without its carried witness's `-- hole:` line (R23).

The finding (testers 2026-10-08, erdos-1094), on the record, first four lines of
targets/erdos-1094/nodes/erdos-1094--h1/Witness.lean:
-- hole: h_fixed_k

import Mathlib


Cause: postmerge.child_proposal wrote the carried text verbatim (R23/AC44 said "byte for byte"),
so the transport line `-- hole: <name>` (F07-Q57 (3): the handle while the node has no id) became
part of the child's Witness.lean.

Readers checked before stripping:
* step 7 stages a carried witness through the same postmerge.child_proposal, so stripping there
  means the checked text is the written text (tested; the lean tier admits the stripped file).
* the verdict's `hole_witnesses` / step 7's `hole-witnesses` diagnostic record the sha256 of the
  carried *file* (attempts/<name>.<n>.witness), which stays in the parent's attempts/ with its
  marker; cli.checked_witnesses holds the file to that hash before anything is stripped, and the
  service binds a submission to that hash (F07-T53). Unchanged.
* nothing hash-pins a merged Witness.lean: statement_hash covers Statement.lean; a gloss's
  lean_hash is of the file as the tree holds it when the gloss is written, so it is computed after
  the strip (existing glosses on already-merged files are not touched: the record is not rewritten).
* no other reader parses `-- hole:` from a node's Witness.lean (grep of gate/opn_gate, api, site);
  graph.witness_is_stub and layout.mentions_sorry do not care about a comment line.

Fix: carried.as_witness(text) drops the first line that carries the name hole_named() read, and,
when that line heads the file, the blank lines around it; every other byte (CRLF included) kept.
postmerge.child_proposal applies it to a carried witness. Reaches the live graph only at a re-pin
(it changes what the post-merge job writes); erdos-1094--h1's file stays as merged.
