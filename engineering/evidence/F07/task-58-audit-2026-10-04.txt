F07-T58 — a merge counts as recorded only if some gate commit names it (audit 2026-10-04)
==========================================================================================

Graph branch: audit-b-workflows (graph worktree opn-audit-graph), commit c9e2c9a27, .github/workflows/gate.yml only.
Not pushed; the lead opens the graph pull request.

Finding. postmerge_batch.py's uncredited() stopped at the first gate commit that was not a replay and
assumed it credited every merge before it. Three gate commits do not: a T55 catch-up (rebuild() lays
the record on main as it is, on top of merges it does not credit), a single run's own commit, and the
case an append's run relies on when it exits at "a later pull request merged on main" (T45) expecting
the later run to record it. So: bot(1), #2 building, #3 append, #2's catch-up `gate: #2` on top of #3,
#4 append -> #4's run recorded #4 only and #3 was lost; and a building merge whose run ended without
crediting it was never replayed once any later gate commit landed.

Fix. uncredited() reads every gate commit in the walk window (WALK_LIMIT), replays included, and
returns the merges in the window that none of them names; None only when the window holds no gate
commit at all. plan()'s in-flight and no-target filters are unchanged. The append exit stays: the
later run now records the append whatever lands between. run-name: "gate: replay of #N" on a
workflow_dispatch, the host's own name otherwise (whitespace falls back).

      after `gate: #4`, #2's replay has not committed, so #6's plan names "2 5", not "5"; once
      `gate: #2 pass (replayed)` lands, the next plan batches "5 7". The replay is idempotent.

Measured against the live graph (origin/main 7f207c7fd, read-only): the new uncredited() over the
400-commit window finds 4 merges no gate commit names — #225, #321, #361, #362 — and all four touched
no target, so plan() sets them aside. Deploying this replays nothing old.

Risk: a merge whose post-merge run fails for good (a bypass the pinned gate refuses, a two-target
merge) is now named by every later plan within the window and replayed each time, failing visibly
each time (C7), where before it was forgotten after the next gate commit.

merges in the window all touched no target."
