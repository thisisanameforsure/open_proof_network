== 2. THE CHANGE ==================================================================================
gate/opn_gate/modes.py
  - STATEMENT_REVIEW_MODES = ("proof", "partial"); STEP9_GRADE = fidelity.SIGNED_FROM
    ("screened-and-signed"); STEP9_REGISTRIES = {"formal-conjectures"} (intake.FC_SOURCE_KIND).
  - Classification gains review_basis ("certificate" | "provenance" | None) and review_reference.
  - needs_review: False for proof/partial when review_basis is set; everything else as before.
  - review_kind (property): "pr-approval" when needs_review, else the basis for proof/partial,
    else None. as_dict publishes review_kind and review_reference (the reference only beside a
    certificate or provenance kind).
  - with_statement_review(graph_root, classification): for proof/partial on target T, the root's
    certificate first, then registry provenance, else unchanged.
  - root_certificate(target_dir): the root's certificates counted as F11-R3 counts them
    (fidelity.counting against fidelity.current_hash: v2 pinned to the root as it stands); if
    fidelity.grade_of(counted) meets screened-and-signed, "fidelity/<newest counting signing
    certificate>". Unreadable certificates or root -> None with a logged warning (C7).
  - registry_provenance(target_dir): target.yaml provenance.statement_source in STEP9_REGISTRIES
    and non-empty upstream_commit and upstream_path -> "formal-conjectures:<path>@<commit>".
    Unreadable record -> None with a logged warning.
gate/opn_gate/cli.py
  - run_classify calls modes.with_statement_review(graph, classification) right after classify.
Unchanged: alternate (no review), curator/intake (reviewers rule; review_kind "pr-approval" when a
second curator is asked, null when waived), appends, proposals, fidelity mode, the tutorial flag
(still the workflow's; the classifier says pr-approval on the tutorial node as it said
needs_review true before), postmerge, the sandbox, the pipeline, products.

== 7. WHAT THE GRAPH WORKFLOW READS ===============================================================
`opn-gate classify --graph . --base <base> --head HEAD` prints one JSON document. T17 adds:

  review_kind       "certificate" | "provenance" | "pr-approval" | null
  review_reference  string | null

  proof / partial, root certificate grade >= screened-and-signed (counting, v2, current hash):
      needs_review: false, review_kind: "certificate",
      review_reference: "fidelity/<subject>-<n>.yaml"   (relative to targets/<target>/)
  proof / partial, else provenance.statement_source "formal-conjectures" with upstream_commit and
  upstream_path non-empty:
      needs_review: false, review_kind: "provenance",
      review_reference: "formal-conjectures:<upstream_path>@<upstream_commit>"
  proof / partial, neither (including the tutorial node; its exemption stays the workflow's flag):
      needs_review: true,  review_kind: "pr-approval", review_reference: null
  curator / intake with a second listed curator:  needs_review: true, review_kind: "pr-approval",
      review_reference: null (reviewers still names who may approve)
  alternate, append, explainer, proposal, fidelity, waived curator/intake, a refused diff:
      needs_review: false, review_kind: null, review_reference: null

Post-merge: pass them straight through —
  opn-gate postmerge ... --review-kind "$review_kind" --review-reference "$review_reference"
  -> attestation review {kind: "certificate"|"provenance", reviewer: null, reference: <ref>}
  (pr-approval keeps --reviewer; the tutorial keeps --review-kind tutorial).
Read both with a default (null): a pin that predates T17 omits them and keeps needs_review true,
which is today's behaviour.
