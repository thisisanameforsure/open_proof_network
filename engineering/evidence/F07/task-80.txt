F07-T80 (bug B7, agent run 2026-11-19): queue.ahead names pull requests nobody waits on
=====================================================================================

Defect. Witness PR #1489 (variant-cce9b284--h6, opened and gate-failed 2026-11-13, idle since) was
first in queue.ahead for every erdos-257 submission, though merged #1504 had filled that slot.
queue_block took every lower-numbered PR of the lane from queue_order(listed); gate state, age and
the slot played no part. The merge actor already passes over a red PR (merge.yml decide), so no
merge was delayed: a display defect. Owner's ruling: drop such PRs from ahead only; close nothing.

Fix (api/opn_api/pending.py):
* slot_filled: a service record of kind witness whose node's Witness.lean on main (read through
  optional_committed, the committed-file cache at main's head, no API call) has no sorry token
  (graph.witness_is_stub's reading, via layout.mentions_sorry).
* idle_red: the open listing's updated_at (new OpenPullRequest field, parsed from the same listing
  call; the fake host carries it) older than settings.queue_idle_red_days, and the PR's state at
  the listed head says waiting_on gate-failed. Only PRs idle past the window cost a state read
  (live_state, cached as before); a red head is remembered per process in
  Context.idle_red_heads (bounded by MAX_REMEMBERED), so an abandoned PR costs one state read per
  process, not one per window. A state the host cannot give, or a moved head, keeps the PR in (C7).
* passed_over feeds both queue_block (ahead, position, of) and the snapshot's entry_queue, so
  GET /submissions/<id> and GET /submissions.json agree. A PR's own entry is never dropped from
  its own lane. queue_order is unchanged, so queue.order is still the actor's list and
  gate/tests/test_finding_queue_order_is_the_actors.py needed no change (4 passed, run against
  the graph checkout read-only through OPN_GRAPH_CHECKOUT; it skips without it).
* QUEUE_ORDER text and gate/agents/AGENTS.md's queue paragraph name the two exclusions.
Config: OPN_API_QUEUE_IDLE_RED_DAYS, default 3 (config.DEFAULT_QUEUE_IDLE_RED_DAYS), documented in
the config module's docstring beside the other windows.
Not done: a PR the service has no record of is never judged under (a), because the service has no
PR-files listing and adding one would be a per-PR host call. #1489 was opened by the service, so
it has a witness record.
