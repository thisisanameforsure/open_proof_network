F07-T65 — reproduce and postmerge refuse a checkout that is not the spec's pin (audit 2026-10-04)

Finding. attestation.build copies ctx.spec["network_commit"] into the record, and neither
run_reproduce nor gate/reproduce.sh compared the gate actually running with that pin. A replay from
a later main, a branch or an edited gate/ wrote a record naming the pinned gate, and --compare could
answer "identical": true for a run the pinned gate never made (D-5 speaks of the pinned gate).

Fix (gate/opn_gate/cli.py, reproduce and postmerge entry points only, plus helpers above
run_reproduce):
- running_network_commit(): git rev-parse HEAD and git status --porcelain -- gate on the repository
  the gate was loaded from (GATE_DIR.parent), through the existing _git (repo variables scrubbed).
- pinned_network_commit(): the target's gate-spec.json at the commit, read with git show before any
  export (target inferred from git ls-tree when --target is absent).
- network_mismatch(): the diagnostic network-mismatch when HEAD differs, when the gate is not a git checkout, or
  (reproduce only) when gate/ is dirty. A pin that cannot be read is not judged; the spec load
  refuses it as before.
- reproduce: refused with {"verdict": "refused", "diagnostic": {...}} and exit 2 before the export,
  the image and the sandbox. --allow-network-mismatch runs anyway, warns on stderr, and with
  --compare adds "network_mismatch" and sets "identical": false (exit 1).
- postmerge: refused the same way only when OPN_NETWORK_COMMIT is set and differs from HEAD
  (dirty is not checked there, as asked). The graph's workflow does not set it, so live runs are
  unchanged; setting it (the pin the job checked out) is the later graph task.
- gate/reproduce.sh: header documents the refusal and the flag; the check itself is in the Python
  it execs.

Tests. gate/tests/test_finding_reproduce_pin.py (9 tests, fast tier). gate/tests/conftest.py gains an

Proposed Q entry (F07-Q-next): A replay speaks for the gate the spec pins, so reproduce compares

in the postmerge job; gate/tools/check_reproduce.py invokes reproduce.sh from the laptop checkout and
