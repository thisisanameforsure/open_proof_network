THREE THINGS THE REAL TOOLCHAIN SAID, THAT GUESSING WOULD HAVE GOT WRONG
-----------------------------------------------------------------------
1. `have h : T := sorry` is an `Expr.letE`, not a beta-redex and not `letFun`. The extractor was
   written against that after printing the term, per the log's "read the shape before asserting
   on it". `sorry` itself is `sorryAx (Lean.Name → T) false <tag>` — the type argument is not T.

2. A theorem's proof term needs `ConstantInfo.value? (allowOpaque := true)`. Without it the value
   is None, `value!` panics, and hole extraction silently reports no holes — which is exactly the
   failure a partial proof must never have. Caught by driving a two-hole fixture and seeing zero.

3. Imports happen once per process. A second `processHeader` in the same run returns an
   environment with no parser extensions, so the second file elaborated loses `∧`, `¬` and every
   other notation and fails with "expected token" at the first one. The metaprogram therefore
   imports once (`OpnGate.Frontend.headerEnv`) and elaborates both files on top of that
   environment. This also solves the real problem: a partial proof declares the statement's own
   name, so the statement and the artifact cannot share one environment the way a statement and
   its witness do — they would be a duplicate declaration, not a comparison.

WHAT IS NOT IN T2
-----------------

and the two test files. The step-2 dispatch and the sorry-tolerant replay belong with the
post-merge work that consumes the holes (T4), which waits on F08-T1 in any case.
