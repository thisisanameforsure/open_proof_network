## green

What changed:
- api/opn_api/githost.py: two Protocol methods on the GitHost seam and HttpxGitHost.
  `close_pull_request(repo, number)` sends `PATCH /repos/<repo>/pulls/<n> {"state": "closed"}` and
  answers the head branch only when it lives in `repo` (None for a fork, so it is never deleted);
  `delete_branch(repo, branch)` sends `DELETE /repos/<repo>/git/refs/heads/<branch>` and answers
  False on 404/422 ("Reference does not exist"), so a repeat is not an error. Every other failure
  is a GitHostError naming the call, never the credential (the seam's existing `_send` rule).
- api/tests/api_fakes.py: FakeGitHost gains both, recording `closed_pulls` and
  `deleted_branches`; a closed pull request then reads closed through `get_pull_request`.
- api/opn_api/withdraw.py (new module, so the change stays out of pending.py and submissions.py,
  which other tasks of the same plan edit): `DELETE /submissions/{id}`. The id is the record's
  ULID or the pull-request number, parsed as the read route parses it. Holder only: the record's
  pseudonym must be the caller's (identities keep pseudonyms unique, F05-R4); an id the service
  never recorded is 404 submission-unknown. Merged is read from the host at the moment of asking
  (get_pull_request, not the service's 60 s cache), so a pull request merged a minute ago is 409
  submission-merged, never "withdrawn". One already closed (by the service before, or on the host)
  answers `withdrawn: true` with no host write. Otherwise the pull request is closed, the branch
  deleted when it carries one of the service's own prefixes (submit/, append/, propose/), and the
  record closed in the store with the state the host was left in, the cache told too, so
  GET /submissions.json drops it at once and the duplicate rule (F07-T35) stops counting it. A
  host failure is 502 withdraw-failed and the record stays open; a branch that cannot be deleted
  after the close is logged, and the answer says `branch_deleted: false`.
  Answer: `{withdrawn, submission (the record document), pull_request, branch_deleted}`.
- api/opn_api/routes.py: the route (authenticated write, F07), D-35 row
  `DELETE /submissions/<id>` added to D35_OWNED_BY_F07, and its purpose line for GET /.
- api/opn_api/mcp/writes.py, bijection.py, schemas/withdraw_submission/v1.json: the MCP write
  `withdraw_submission(submission_id)`, bearer required, passing the route's envelope through.
- docs/architecture_decisions.html: D-28's write table and D-35's plain-path table gain the
  withdraw_submission row under the notation note of 2026-09-24 (the owner's ruling D5 approved the
  route; the bijection and routes tests quote D-28 and D-35 verbatim). No decision changes.

Existing tests extended, none deleted: test_routes.py (F07's write set and its D-35 row),
test_mcp_surface.py (WRITES and the result-schema arguments), test_mcp_auth.py (MINIMAL: refused
without a bearer), test_mcp_equivalence.py (AC4 row: one DELETE, the same answer as the route on
a second harness), test_finding_argument_renames.py (a second path-only write).
