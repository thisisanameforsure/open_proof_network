2. The change
-------------
store.py      Submission record; Store gains put_submission, get_submission, get_submission_by_pr,
              list_open_submissions, close_submission. MemoryStore: three dicts/sets. DynamoStore:
              key prefixes in the existing tokens table, no TTL — submission#<ulid> (the record),
              submissionpr#<n> (pointer), submissions#open (a string set updated with ADD/DELETE,
              atomic on DynamoDB's side). No fourth table: adding one is a stack update, and R13
              answers 503 between the code deploy and that update.
githost.py    PullRequestState {number, url, state, merged, mergeable_state, head_sha,
              merge_commit_sha, runs[{name,status,conclusion,url}], reviews[{login,state}]};
              GitHost.get_pull_request(repo, n) = GET pulls/{n} (404 -> None), GET
              pulls/{n}/reviews, GET actions/runs?head_sha= — Actions runs rather than check-runs,
              because Checks: read is not a permission C8 lists. One page (100) of each.
app.py        CachedPull and Context.pulls only (ApiError untouched).
pending.py    new. record() — a store failure is logged at ERROR and the route still answers 201
              (the pull request exists; the record is advisory, C7/C9). GET /submissions/{id}:
              ULID (case-insensitive) or a number with any leading zeros; malformed -> 400
              submission-id-invalid. Live state cached for frontier_max_stale_s; a host failure
              serves the last state with pull_request_error (no last state: pull_request null +
              the error); a fresh read that finds the PR merged or closed closes the record with
              that state, so it is never looked up again. Attestation: kinds outside POST
              /submissions' artifact types -> no-attestation-for-mode; known unmerged ->
              not-merged; else attestations/<n:06d>.json when on main (note null), otherwise
              attestation-pending (merged, the post-merge commit not there yet) or
              pull-request-unavailable (host could not say, nothing on main). No record: answered
              only when main has the attestation (submission null); otherwise 404
              submission-unknown WITHOUT a host lookup, so nobody can spend the App's rate budget
              by enumerating numbers. GET /submissions.json -> {snapshot_at, open}.
routes.py     GET /submissions.json, GET /submissions/{submission_id}; unauthenticated reads, d35
              None, feature F07.
appends.py    append_pr takes kind/target_id/node_id and records (postmortem, annex,
              approach-record).
proposals.py  open_proposal takes kind and records (speculative, variant, witness).
requests.py   NOT in the plan's file list, but it calls appends.append_pr, whose signature changed
              (the suite caught it: TypeError -> 500 on /defect-claims). It now passes
              kind revision-request / defect-claim, so those pull requests are recorded too.
api_fakes.py  FakeGitHost.set_pull_request_state(number, *, state, merged, mergeable_state,
              head_sha, merge_commit_sha, runs, reviews), pull_lookups, pr_lookup_failure,
              get_pull_request (a PR the fake opened defaults to open/unmerged/no runs/no reviews;
              any other number is unknown).
api-deploy.yml  opn_api/pending.py added to the package check's entry list.

  "needs the submissions.py record call; after the other session's commit". No assertion edited.

New tests (api/tests/test_pending_submissions.py, 26; test_githost_seam.py, 5 for the seam):
  the append routes and a witness proposal record their kind; a store failure still answers 201
  and logs ERROR; ATTESTING_KINDS == submissions.ARTIFACT_TYPES; 1 / 000001 / 0000000001 / ULID /
  lower-case ULID are one answer; 0, 000000 and a 13-digit number are 404 with no host lookup;
  malformed ids are 400; the window is one lookup, an aged read looks again, a failure serves the
  last state and closes nothing, the next read retries; a failure on the first read ever is a
  null state with the error; a number the host no longer knows is a null state with the error,
  cached for the window; closed-unmerged closes the record and a cold app answers with no lookup;
  merged proof -> attestation-pending, then the attestation with no further lookup; the snapshot
  drops a merged record; MemoryStore and DynamoStore parity (round trip, closing, the index
  emptying, the three-prefix layout with no expires_at). Seam: the three GETs and their shaping,
  404 -> None with no reviews call, 403 names the call and GitHub's message and no credential,
  transport failure and a non-array reviews body are GitHostErrors, no head sha -> no runs call.
