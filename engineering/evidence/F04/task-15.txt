F04-T15 · the statement page shows the Lean itself: the proof, the witness, every partial (Q17) · 2026-09-18

The finding (Mike, 2026-09-18): "right now the proofs are links to github. How can we bring them into the site
in a way that makes sense?", citing https://openproofnetwork.org/problems/erdos-402/#node=erdos-402--h1
A node's Statement.lean has been rendered into its page since T1, but the proof was one sentence and a file
link, so the redesign's "View the proof →" button led to a page containing no proof. On erdos-402--h1 — proved,
40 lines of real tactic proof — a reader was sent to github to see any of it.

Decisions (Mike, in the session): all three artifacts, not only proofs; the whole file, hash-verified; the
statement page as their home, not the problem page's panel. The fourth decision was his reversal, below.

What changed
  model.py     LeanFile (path, text, content_hash, attested_hash; .verified, .mismatched) and PartialView
               (the file plus the postmortem's typed fields). NodeView gains proof, witness, witness_open,
               partials. _lean_file reads the bytes and hashes them; _partials_for pairs each attempts/*.lean
               with the record whose artifacts.partial_proof names it. A non-UTF-8 artifact is a named
               SiteError. Reuses the gate's graph.witness_is_stub rather than testing for "sorry" in the text.
  render.py    lean_artifact (a captioned <pre class="lean">), witness_block, partials_block; the proof block
               keeps its merge-commit link and appends the text; NO_WITNESS_OWED.
  node.html    a Witness section between Proof and Attestation; the partials under Attempts.
  site.css     .artifact, .artifact-cap, and the pre margins inside a figure and a prose-block.
  fixture.py   attest() now computes artifact_hash from the Proof.lean in the tree (the sample carries a
               placeholder, "d"*64); WITNESS_STEP so a run recording step 7 exists; two partials, one named
               by a postmortem and one named by nothing, the payload in the Lean.

What each artifact may claim — the load-bearing part
  Proof.lean      attested. attestation/v4 carries artifact_hash, so the caption says the bytes are the ones
                  the gate checked, and only a proof's caption can say it.
  Witness.lean    not hashed anywhere in the protocol. The caption names the step that checked it — step 7 of
                  the run recorded on the page, or, when that run lists no step 7, that the gate checks it on
                  every submission. It never claims the bytes were attested.
  attempts/*.lean covered by no attestation at all: an untrusted block (R4) beside the postmortem naming it,
                  or beside the fact that none does.

Two defects found while building it, both in my own first design
  1. Severity. The first version raised SiteError when a proof's bytes were not the attested ones. That took
     the whole site down: 49 errors and 70 failures across the suite, because the sample attestation's
     artifact_hash is a placeholder. The blast radius was the real bug, not the fixture — one node's defect
     deciding whether the graph has a site is the rule the products learned on 2026-09-17. Put to Mike, who
     reversed his own earlier choice: the text is withheld with both hashes named and every other page renders.
  2. The superseded slot. The witness block invited a reader to fill any open slot. On the live graph 6 of the
     12 nodes with an unfilled slot are superseded by a D-8 revision, so the page was asking for work nobody
     owes — the shape F03-T10 fixed on the frontier one day earlier. The first fix keyed on the gate's
     witness-missing cause and was wrong the other way: blocked_because sets that only for a compiler-derived
     hole that is blocked, so a hand-authored node with an open slot has no cause and was silenced wrongly
     (caught by the existing open-slot test going red). Final rule: withhold the invitation from
     superseded/abandoned/refuted, invite on every other open slot. Both branches are pinned by tests.

Red first

  checker's constant, and a non-UTF-8 refusal that cannot fire on a node file — layout.check_imports decodes
  Statement/Proof/Witness/Context before load_node returns, so the refusal is reachable only for a partial,
  which is what that test now drives). 2 more added for the superseded slot: 20 in the file, 223 in the suite.
