F04-T31 — the site says how a problem was resolved (follow-up to F03-T17; D-33 as written, v3.28)
Branch audit-s-followups, 2026-10-04.

Finding: since F03-T17 a target is `resolved` when its root is proved, refuted (merged
counterexample) or defective (merged vacuity certificate). The site turned `resolved` into
"proved" everywhere it named a problem's status: Renderer.problem_status (the tag and the card's
data-status, hence the Problems "Proved" filter), stage_marks, the Problems page's Proved count,
target_claimable ("Proved: the problem's own statement is closed"), the steward card ("This problem
is proved but not explained"), the target page's section heading ("Proved, explained, written up")
and the digestion counts ("proved nodes in the closing proof's dependency closure"). A conjecture a
counterexample settled read "proved".

Change (site/opn_site/render.py, templates/target.html, templates/states.html):
- Renderer.resolution(tv): the word follows the root's status in graph.json —
  RESOLUTION_WORDS = {refuted: "disproved", defective: "shown ill-posed"}, anything else
  (a proved root, or a root left open under a proved resolves-variant) reads "proved".
- problem_status, stage marks, the claimable sentence ("Disproved: a counterexample is on the
  record, so ..." / "Shown ill-posed: a vacuity certificate is on the record, so ..." /
  "Proved: a proof is on the record, so ..."), the steward card, the section heading and the
  digestion counts ("settled nodes in the closing counterexample's dependency closure") use it.
- The Problems "Proved" count is now the set its filter shows (data-status="proved"); a
  disproved problem is under All only.
- Vocabulary: PROBLEM_STATUS_DEFS and the Docs problem key (STATE_MAP_PROBLEM_KEYS, five words
  -> seven) gain "disproved" and "shown ill-posed"; two Glossary rows (keys disproved,
  ill-posed; protocol "resolved · root refuted/defective"). The Docs problem state map's
  resolved box reads "site: proved · disproved · shown ill-posed" and names the three artifacts;
  the arrow reads "the root is settled, or a resolves-variant proved"; the actions table's
  Refute/Show-vacuous rows say what happens at the root. Docs golden regenerated (only page
  that changed).
- Tests restated, not deleted: two renderer stubs carry the root's status and `resolution`
  (test_finding_tutorial_page, test_finding_resolved_target_open_variants); the Docs key regex
  admits a hyphen (test_docs_states).
- Held to the products: test_the_site_words_follow_the_products reads every target's graph.json
  root status from disk and asserts the card's word is the one it calls for.
- Fixture: fixture.build_with_resolutions (three open-track targets, each root settled by a
  proof, a counterexample or a vacuity certificate via the gate's own test helper `settle`).
