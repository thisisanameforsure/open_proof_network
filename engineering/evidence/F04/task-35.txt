Defect (a): /nodes/erdos-1094/erdos-1094/ and /nodes/erdos-1094/erdos-1094--h3/ said "author not
recorded; no postmortem record names this file. No attestation covers a partial". The record:
attestations/000441.json (erdos-1094) and 000448.json (erdos-1094--h3) are attestation/v6,
verdict pass, merged (305fb84fc6d8, 68f75c7ed2f0), submitter t1008-a, artifact_hash null, and
step 2's diagnostic is `partial-submission` with details.path = the attempts/ file on the page;
ledger/t1008-a.json credits both.

Cause: model._partials_for looked for an author in a postmortem/v1 record only
(artifacts.partial_proof). Nothing on the site read the attestation that filed the partial. The
attestation's artifact_hash is null by design (nothing in the protocol hashes a partial), so the
alternates' by-hash lookup cannot find it either; what links file to attestation is step 2's
`partial-submission` path, which the gate already reads in graph.partials_of (F18-T4).

Fix: model._merged_partials calls graph.load_attestations + graph.partials_of (passing, merged,
this node, its current statement hash, step 2's path), and PartialView carries the attestation's
path, merge commit and submitter. render.partials_block names the submitter ("by t1008-a"; the
postmortem's contributor when no attestation names one; both when they differ) and "merged in
<commit> under attestations/NNNNNN.json, whose step 2 took this file as a partial". It still
reads as an attempt, never a proof (F03-Q7): the provenance stays "Untrusted contributor text",
and the words are "A partial records an attempt, not a proof: the gate replayed it with its holes
left as sorry" and "no hash in the record binds these bytes". A partial no record names renders
exactly as before (goldens unchanged for the partial blocks).

Defect (b): /nodes/erdos-1094/erdos-1094--h1/'s Attestation block showed toolchain, Mathlib,
reviewer and steps, never `submitter` (t1008-b in 000450.json).
Cause: attestation.html had no row for it. Fix: a "Submitter" row, `<code>name</code>`, or "not
recorded" for older attestations whose submitter is null.
