F03-T23 — a postmortem's attempts line carries the record's own model_and_tooling (B6, 2026-11-19 agent run)
Date: 2026-11-19. Branch f03-t23-postmortem-tooling, from origin/main 867c11b7.

CAUSE
gate/opn_gate/cli.py `_write_merge_entries` computes the merge's tooling once, from the merge's
attestation (`ledger.merge_tooling`, gate/opn_gate/ledger.py), and passes it to every entry.
An append (postmortem) merge has no attestation, so that is always "undeclared". The postmortem
branch of `_merge_entries` already loaded the record (`recordsmod.load_postmortem`) for its
route_class but never read the record's own top-level `model_and_tooling` (postmortem/v2,
required, null or a 1-200 char string; v1 has no such field). So every attempts line said
"undeclared" whatever the record declared.

FIX
- gate/opn_gate/ledger.py: `postmortem_tooling(record, *, fallback=UNDECLARED)` beside
  `statement_tooling`: the record's declared string, else `fallback` (null, blank, or a v1 record).
- gate/opn_gate/cli.py `_merge_entries`, postmortem branch: `tooling=ledger.postmortem_tooling(
  record, fallback=tooling)`. The merge's tooling stays the fallback, so nothing changes for a
  null or v1 record. `automation` unchanged (postmortem has no automation field).
