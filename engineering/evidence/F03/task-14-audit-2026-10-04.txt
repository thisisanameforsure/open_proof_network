F03-T14 — a closed root is not claimable work (audit 2026-10-04)
==================================================================

Finding. targets/index.json published `claimable: true, not_claimable: []` for
(a) a pre-F11 target whose root is proved (status `resolved`): products.target_facts returned the
    declaration's flag / the root's tutorial bit and never consulted the status — the live
    `tutorial` target;
(b) a target whose root is refuted, defective or abandoned: only `proved` makes a target
    `resolved`, so the status stays open (`listed`/`active`/`dormant`, all CLAIMING_STATUSES) and
    intake.claimability, which read only the status, said yes.

Fix (gate/opn_gate/intake.py, gate/opn_gate/products.py):
- intake.CLOSED_ROOT_STATUSES = (refuted, defective, abandoned); intake.root_reasons(root_status)
  gives `root-<status>`; intake.claimability takes `root_status` and adds that reason.
- products.target_facts: a pre-F11 target that would be claimable gets reasons `status-resolved`
  (when resolved) plus root_reasons(root status); claimable is false whenever there is a reason.
  A pre-F11 target declared NOT claimable keeps its empty reasons (Q4), so open_beneath does not
  reopen the nodes beneath it.
- products.open_beneath also accepts `root-<status>` reasons: a closed root is a fact about the
  root (Q15), so the frontier beneath it does not move. Net effect on frontier.json: none.
- intake.explain words `root-<status>`; the fixed reasons moved to intake.FIXED_REASONS (ruff
  PLR0911), same words.
- Target status word unchanged (D-33: whether a refuted root makes a target `resolved` is the
  owner's call). No schema change: targets-index/v7's not_claimable pattern admits `root-refuted`;
  its description names only F14/F15 reasons — a description refresh waits for the next version.

Goldens: none changed (test_golden passes for all three states; the fixture's resolved/closed-root
cases do not occur in the golden states). api/tests fixtures copied from goldens: unchanged.
Site: no change needed (site/opn_site/render.py already calls products.open_beneath and
intake.explain).
