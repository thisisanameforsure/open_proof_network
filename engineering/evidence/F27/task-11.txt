Design (stated for agent D and the lead):
- SufficientSet.settles: "proves" | "refutes" (routes.PROVES / routes.REFUTES), in as_dict.
  A set's id is unchanged: _set_id over members + assemblies, so every proving id on the live
  record stays where it is.
- Order of Routes.sets (record order, never ranked): the proving sets first — the root's routes
  in merge order, then its direct proof, then each resolves variant in the rows' (sorted) order —
  then the refuting sets, one group per refutes variant in the rows' order, each variant's routes
  in merge order then its direct proof.
- Domination (_minimal, cut="any") and the cap are applied per side: bounded() is called once per
  side. The cap max_sets is OVERALL: the proving side is bounded at max_sets, the refuting side at
  what is left; a refuting set past the cap sets truncated.
- `shared` counts a statement held by any other set of EITHER side (the gap lemma of erdos-257 is
  used on both sides, D-25 v3.46).
- Root proved: no refuting sets (nothing to refute). Root refuted: no proving sets (the resolves
  variants are not closed either); refuting sets are enumerated only while the root is neither
  proved nor in DEAD_STATUSES (the brief's rule), so a refuted root lists no set at all.
- selector_tree: with sets of both sides the top node is a FORK: route None, node None, set
  None, side None, sets = all; exactly two children, in this order: the proving family
  (side="proves") then the refuting family (side="refutes"); each child is what _split gives that
  side's sets alone (a leaf when one set, else the split), with `side` set on the child only —
  never on its descendants. With one side only the tree is as before and `side` is None on every
  node. Selector.as_dict carries "side".
