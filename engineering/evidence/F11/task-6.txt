R11 asks for one driver that exercises both contributor paths with a test identity each —
claim, precheck, submit; a postmortem; a variant; the root closing; the site — with timings.
Before T6 the pieces existed as three smoke tools (smoke.py, smoke_precheck.py, smoke_mcp.py),
each proving one seam, none of them the sequence a contributor lives through.

  gate/tools/rehearsal.py       the driver: mints an identity per path the account-free way
                                (D-19), runs the four acts on each path, polls the root,
                                checks the site's rendered-from commit against the service's,
                                writes the readiness record with a time per step. Exit 0 only
                                when every R11 step passed; 2 (PENDING) when a step was
                                skipped for want of an input, the merge has not landed or the
                                site is a redeploy behind; 1 on a failure. HTTP through the
                                smoke tools' guarded caller (https or the local runner only,
                                C5); MCP through the SDK client, the one Claude Code speaks.
  gate/tests/test_rehearsal.py  fast tier, over the walkthrough test's stage (a git checkout
                                of the fixture graph, the api on a loopback port, the fake
                                host whose precheck runs finish at once): every act ok on both
                                paths, two pull requests of each kind on the host, the root
                                pending, the site skipped, exit 2; the optional steps skipped
                                without inputs; a node off the frontier fails the first step;
                                only https or the local runner is driven.

Two things the live run taught (below), both folded in before the commit:
  - the MCP path's variant is marked with a trailing comment, because a variant's id is a hash
    of its statement (F08-R3) and the second path would otherwise have proposed the node the
    first had just proposed;
  - a skipped step is PENDING, not READY: the live run printed READY with four steps skipped,
    which is not what R11 means by "every step". The test pins the rule.
