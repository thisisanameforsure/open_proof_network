The defect. fidelity/v1 records no statement hash and grade_of took the latest certificate for a
subject *name*, so after `opn-gate revise` changed the root's statement the target stayed
screened-and-signed and claimable with the old signer counted, while the same index row said the
root's QA was stale. D-9: non-author sign-off is "the only event that changes accepted state";
F12-R9 ties a signature to "the QA record for the current statement hash".

The rules (Mike, 2026-09-13), as built:
  - fidelity/v2 = v1 + required statement_hash (64 lowercase hex): qa.subject_hash(target, subject)
    at the moment the certificate is written. Every new certificate is v2; v1 stays readable (D-34).
  - A certificate counts toward a subject's grade, signature count and signers only if it is v2 and
    its statement_hash equals the subject's current hash. v1 counts for nothing. A subject with no
    counting certificate is mechanical-only with no signers. Root and every definition alike.
  - The grade is the latest *counting* certificate's; a later non-counting one masks nothing.
  - After a root revision: not claimable, reason grade-below-screened-and-signed (no new code).
  - Superseded certificates stay on disk and are not published (no targets-index bump).
  - A Mathlib pin move does not drop the grade; a revised root keeps its D-10 posting.
  - A certificate for a definition that no longer exists has no current hash and counts for
    nothing; its row stays (see "not settled" 1) and nothing crashes.

  F11-Q30 — A certificate is for a statement (2026-09-13, finding C; Mike's rules). fidelity/v1
  pinned no statement, so a signature crossed a D-8 revision under the subject name `root` — the one
  record on the path from QA to claimable without a hash (F12-R10 already refuses to carry an
  attempt across one). Decisions: (a) fidelity/v2 adds a required statement_hash, the value
  qa.subject_hash gives (the root's statement hash, a definition file's content hash), written by
  attest, so intake's mechanical-only certificates carry it too. (b) A certificate counts only if it
  is v2 and pins the subject's current hash; the grade is the latest counting certificate's. (c) v1
  counts for nothing above mechanical-only until re-signed at v2 — no migration, because the nine
  live v1 certificates are all mechanical-only and no live grade moves; authorship still reads from
  v1, so the non-author rule holds across versions. (d) The pass being fresh is not enough: D-9 makes
  non-author sign-off the only event that changes accepted state, so re-running the screens on a
  revised statement lifts nothing (the rejected fix, held by
  test_re_running_the_screens_does_not_resurrect_the_old_signature and a mutant). (e) The pin is not
  in the hash: D-9 re-runs the screens when the pin moves, but the statement the signer read is the
  same, so the grade stands while the QA pass reads stale. (f) Superseded certificates stay on disk
  and are not published; no targets-index version, no new not-claimable reason. (g) A certificate
  for a definition that no longer exists has no current hash and counts for nothing; its row is
  kept at mechanical-only (F11-T2's no-silent-rise rule). Reversal: to let v1 signatures count again,
  treat a v1 certificate as pinned to the hash current at its date (needs history, not the tree); to
  drop the pin rule, count every certificate (mutant_nohash restores exactly that and turns the seven
  finding-C tests red); to drop removed-definition rows, filter subject_grades to subjects_of.
