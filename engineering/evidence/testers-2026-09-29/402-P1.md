## Mathematics

- **variant-9724698e (card 13)**: 402-C's `Proof13.lean`, unchanged, checked by /check verify against the merged node (22:06:50Z, okay, lint []), verdict pass from precheck 01M3QKAEFGPFXJ5KTTWYNRDBKR; submitted as PR #304.
- **What the card-n route needs, exactly (python, not machine-checked in Lean).** In the route every card-n variant uses (M = max A; if no x has n·gcd(M, x) ≤ M, each other x is M·j/k with k < n, i.e. L·x = c·M with c = L·j/k, L = lcm(1..n−1)), the proof closes iff the "bad" graph on the values c (edge when n·gcd(c, d) > max(c, d)) has **no clique of size n − 1**: the n − 1 other elements give n − 1 distinct values, and a good pair among them is the conclusion. A proper (n − 2)-colouring (the certificate wave 1 used) is a sufficient witness of that, not a necessary one. Computed the clique number ω exactly (networkx `max_weight_clique`, `402-P1/clique.py`, output `402-P1/clique-numbers.txt`): **ω = n − 2 for every n from 5 to 70** (n = 70: 1469 values, 102911 bad pairs, ~1 s each), and a maximum clique is always present in the form {j/(n−1) : 1 ≤ j ≤ n−2} (plus others, e.g. the multiples of 1/(n−1)'s divisors). So the route never breaks through n = 70, and the certificate is only a matter of cost.
- **Why it cannot break, and what that says about the root.** Given an (n−1)-clique of values c_1..c_{n−1}, the set A = {L} ∪ {c_i} has n elements, every pair (L, c_i) is bad (c_i = L·j/k with k < n gives gcd(L, c_i) = (L/k)·gcd(k, j) = L/k for j/k in lowest terms, and n·L/k > L), and every pair (c_i, c_j) is bad: A is a counterexample to Graham's conjecture. Conversely the route shows any counterexample yields such a clique. So **Graham's conjecture (Erdős 402) is equivalent to: ω(bad graph for n) ≤ n − 2 for every n** — the Balasubramanian–Soundararajan theorem therefore guarantees every card-n variant is provable by this route, and a proof of the root through it would need a general argument bounding the clique number, which is exactly the hard part (the graph's cliques of size n − 2 are plentiful, so there is no slack). Reasoned by hand, not machine-checked; the reduction direction "route ⇒ statement" is what the merged card proofs check in Lean for n = 8..10 (and #252, #258/#304 when merged).
