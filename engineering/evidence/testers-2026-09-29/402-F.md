## Mathematics

- **spec-48bd0126 `Opn.erdos_402_max_fraction_form`** (statement merged by #226; proof PR #257, precheck pass, authoritative gate green, in the merge queue). ∀ n A (hne), 0 ∉ A → (∀ x ∈ A, M < gcd(M,x)·n) → ∀ x ∈ A.erase M, ∃ j k, 1 ≤ j ∧ j < k ∧ k < n ∧ k·x = j·M, where M = A.max' hne. This is the structure step every card-n variant repeats. It is parametrised by n so that it applies directly to the `push_neg` of the card-n case split.
- **spec-fa8046e4 `Opn.erdos_402_card_of_colouring`** (statement merged by #230; proof PR #288, precheck pass, gate green, in the queue). It is the whole card-n argument as one reduction. Suppose n ≥ 2, L > 0, and every L·j/k with 1 ≤ j < k < n is an integer lying in S. Suppose also that c colours S with n − 2 colours so that any two distinct values of the same colour have n·gcd(a,b) ≤ a or ≤ b. Then every A with 0 ∉ A and |A| = n contains a, b with gcd(a,b) ≤ a/|A|. The proof contains both the structure step and the transfer gcd(a,b)·M = L·gcd(x,y).
- **Certificates.** With L = lcm(1..n−1), a greedy DSatur colouring (cert.py) exists and is independently re-verified (gen.py) for every n from 3 to 30 and for n = 35, 40, 45, 50 and 60. This is Python evidence, not Lean. A colouring is sufficient but not necessary, and it has never failed so far.
- **Cards closed by the reduction.** Card 16 (#264) and card 18 (#279) are complete proofs of open variants: the reduction is inlined as `have red` and applied to the certificate with `decide +kernel`. Both had precheck pass and authoritative gate green, so a 95-element S passes step 4 in the real gate. Cards 9 and 10 were done the same way (V9, V10: /check verify okay) and were not sent (402-A and 402-B have their own). Card 25 is a new variant (#285) that declares the reduction as a dependency; its proof is one `exact` (P25-final: /check okay in 13.5 s with the dep pasted in).
- **Lean cost.** Plain `decide` hits maxRecDepth at n = 16. `decide +kernel` fixes that. At n = 25 the `if`-chain colouring and the `{…}` Finset literal hit maxRecDepth, and a `List.lookup` colouring with `List.toFinset` fixes that. AXLE times through the reduction: n = 16: 1.7 s, 19: 3.9 s, 20: 5.4 s, 25: 14.1 s. The /check 20-s budget therefore caps this route at about n = 25 or 26. The gate's own cap is untested beyond n = 18.
