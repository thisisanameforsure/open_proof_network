F28-T11 (bug B5, the 2026-11-19 agent run): a node proved by closure takes alternates
Branch f28-t11-closure-alternate, from testers-1119-correctness (= origin/main 867c11b7).

THE BUG
Graph #1508 proved the parent's last hole; the agent then submitted the parent's assembly as its
Proof.lean (#1519), as gate/agents/AGENTS.md told it to. The post-merge closure sweep proved the
parent by nodes/<id>/closure.json (no Proof.lean); the service's racer conversion
(api/opn_api/racers.py convert, keyed on the row's proof_commit, which a closure row carries from
the partial's attestation) moved the file to attempts/<ts>-<pseudonym>-alternate.lean; the gate
refused it `alternate-unproved`, because modes._has_proof and paths_step.take_alternate both asked
only whether Proof.lean exists.

OWNER'S RULING
A node proved by closure counts as proved; an assembly or direct Proof.lean submitted against it
merges as the node's alternate; precheck says the sweep has closed (or will close) the node; the
guide drops the instruction to submit assemblies after the holes are proved.

   Proof.lean and no proving closure".
2. gate/opn_gate/graph.py load_nodes: `proofs` is built for artifact "proof" as before, and also
   for a node with no Proof.lean whose closure record proves it, so a merged alternate appears in
   proofs[] (graph.json's `proofs`, kind "alternate", already in the schema: no schema change).
   proof_for already set the node's `proof` to the partial's attestation, and still does (the
   alternate's hash is excluded), so status, proof_commit and trust_base are unchanged.
   NodeFacts.rests_on: an alternate first in a closure node's proofs is not what the closure
   rests on; the closure keeps following deps and uses, as before the alternate arrived.
3. api/opn_api/precheck.py `closure_note`: when the bundle adds the node's Proof.lean or an
   alternate, and the committed graph.json row is proved with a `closure` object and no kind
   "proof" among its proofs -> {node_id, state: "closed", link, message}; else when
   closing.closable(graph) names the node -> {node_id, state: "closable", ready, link, message}.

   does not repeat it). Precedent: `carried_witnesses` / `carried_proofs` / `proposal.message`,
   per-topic advisory keys; there is no generic notes field and the HTTP body has no schema
   (MCP precheck_submission passes `body` through as an open object).
4. gate/agents/AGENTS.md: the sufficient-sets paragraph (a set all proved needs nothing more; the
   sweep proves the node, `closable` names those about to close); "After the skeleton merges"

   still accepted and lands as an alternate once the sweep has closed it); "When a hole has been
