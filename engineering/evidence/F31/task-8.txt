## Decisions (proposed Q entries)

- proposed Q: the refusal is placed where each route already judges the node (check_open for
  precheck and submission, off_frontier for a claim, hole_awaiting_witness for a witness,
  proposed_for_node for a proposal), and a shelving outranks blocked/superseded in the order of
  checks, because it is a person's judgment over whatever the derived status says. Variant
  proposals attach to the root, which is never shelved, so they need no check; a proposal whose
  `deps` name a shelved node is not refused (a shelved proved statement is still a fact a proof
  may rest on, Q6), and the lead may want a rule for a shelved *unproved* dep — left as is.
- proposed Q: POST /check's warning carries the whole `shelved` object (not only the cause),
  one shape with the refusal's details and the row.
