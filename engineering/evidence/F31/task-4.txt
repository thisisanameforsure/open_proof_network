## Decisions / proposed Q entries / notes for the lead

- proposed Q: **a retirement is read off the holes.** `graph/v15` publishes `shelved` on the
  rows a record reached, not on `decompositions[]` (closed, `additionalProperties: false`), so
  `routes.read` and `closing.links` know a route is retired when one of its holes carries a
  route-scope shelving whose `via` is the route's node. Exact for every case the derivation
  produces except one: a retired route *all* of whose holes another live route still needs
  leaves no mark on any row and reads as live (it still closes nothing new, since the live route
  covers the same holes). A `retired: bool` (or the record) on `decompositions[]` in the next
  graph version would make it exact; that is a contract change and the lead's.
- **`Route.retired` and `Hole.shelved` are not in `as_dict`.** `list_sufficient_sets/v4.json`
  is closed over routes and holes (nine `additionalProperties: false`), and the api validates
  the result against it, so publishing the two fields is a v5 of that schema — the service
  agent's file (the brief already routes its wording change there). `live` carries the effect
  today, and the site reads the dataclass (`r.live`), not the dict.
- `Summary` is unchanged for the same reason (its dict is published under the same schema); the
  counts the brief mentioned would be a v5 field too.
- A shelved open statement taken *directly* (a lemma a node depends on) also closes nothing, so
  a node whose only path rests on a shelved lemma has no set at all; the test pins it.
