## Decisions (proposed Q entries for the lead to number)

- proposed Q: the brief's `400 bad-field` for a bad action/scope/route is emitted as the
  existing `arguments-invalid` with `details.field`, as every F23/F05 body check does, so no new
  code was added for a shape the catalog already names.
- proposed Q: `already-shelved` is judged against the node's OWN record only (`shelved.via ==
  node_id and scope == node`): a node shelved by inheritance may still carry its own shelving,
  because its own latest record decides for it before any inherited one (rule 4) and so changes
  what a later unshelving of the ancestor does. For scope=route it is judged as "every hole node
  of that decomposition is shelved with scope route via this node"; a route with no hole node on
  the record is never already retired. `not-shelved` is judged only when the row's `shelved` is
  null (and, for scope=route, no hole is retired through it), as the brief says.
- proposed Q: `node-used` is refused only for action=shelved; an unshelve on a used node is
  `not-shelved` (it cannot be shelved), which is the truer answer.
- proposed Q: the duplicate rule's `written` is `node action scope route` (not the cause), so a
  second identical act while one is open is refused as a duplicate whatever its wording, as the
  literature confirmation's is.
- Merge note for the lead: the gate agent registers its own shelving codes in
  gate/opn_gate/codes.py (shelving-signature, shelving-signer-unlisted, and possibly node-root /
  node-used / shelving-route-unknown with source "gate"); where both branches add the same key
  the row should become source "both" at the merge.
