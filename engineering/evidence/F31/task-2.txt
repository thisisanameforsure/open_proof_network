## Decisions / proposed Q entries

- proposed Q: **an unsigned record is `record-invalid`, not `shelving-signature`.** The
  contract makes `key` and `signature` required strings, so a record with neither fails the
  schema before any signature rule runs (one `record-invalid` per missing field). The brief
  asked for `shelving-signature` here; the schema is the contract and the code says what is
  true. `shelving-signature` is what a tampered record, or an approval-key record under another
  key, gets.
- proposed Q: **`shelving-node`**, a code the brief did not list, mirrors `literature-node`: a
  record whose `node` is not the directory it sits in, or names a node the target does not
  hold. Both are refusals the literature check already has and nothing else in the code list
  covered.
- proposed Q: **a tree that does not load is `graph-unreadable`** (the existing `both`/step-8
  code), since the root and the used set are facts about the whole target.
- **Rule 4 read as "latest per key"** (`shelving.Standing`): the node's standing is its latest
  `scope: node` record; each route's retirement is the latest record naming that route. A
  second route's retirement does not lift the first, and an `unshelved` record lifts the key it
  names (`scope: node`, or `scope: route` with the route). The brief's "own latest record"
  would otherwise make retiring route 2 after route 1 un-retire route 1. Noted here for the
  lead; the derivation (T3) is built on it.
- No idempotence rule in the gate (append-only; the service refuses an act that changes
  nothing): `test_a_second_shelved_record_on_a_shelved_node_is_an_append`.
