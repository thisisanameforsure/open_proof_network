  author, date, key_path, signer)` — one `shelving/v1` record (`via: ssh`, signed with the
  signer's own key through `signed.sign`, validated against the schema before it is written)

  `status` uses: branch, one commit, the push printed as `next`); `shelve` in
  `CURATOR_COMMANDS` so a `GraphError` on the way is a refusal, not a usage error.

What the tests pin:
- `shelve and-reassoc --cause … --author alice-steward --key <alice>` writes
  `targets/propositional/nodes/and-reassoc/shelving/20261024T100000Z-alice-steward.yaml`;
  the record validates, `via: ssh`, verifies under its key; `load_target` derives the node and
  its hole children shelved; the record passes `check_shelving_record` as a pull request Alice
  opens (her steward key); `--unshelve` at a later date lifts it.
- `--route attempts/…-partial.lean --branch steward/retire` writes a `scope: route` record,
  the branch holds exactly that file; the node itself is not shelved and its hole is, `scope:
  route`.
- the root → `node-root`; a node the root's proof uses → `node-used`; an unknown route →
  `shelving-route-unknown`; a blank cause; an unknown node: each exit 1 with `{"ok": false,
  "refused": "<code>: …"}` and nothing written; a proved, unused statement may be shelved.

## Notes

- `--date` is the record's `date` (second precision, `Z`) and its stamp, as `status` does;
  the gate's own rule for the record's order is `(date, file name)`.
- The hand path signs with the signer's own key, so the merge's `check_signer_opener` wants
  the record opened by the signer, or signed with their steward commit key — the live shape
  for a curator (no key on record) is: open the pull request yourself.
