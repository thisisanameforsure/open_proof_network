## Decisions / proposed Q entries

- proposed Q: **which proposals "attach" to a shelved statement.** A whole-node proposal is
  refused only through its `proposed-for` record naming a shelved node. A variant attaches to
  the root (never shelved); a dependency on a shelved *proved* statement is use, which Q6 says a
  shelving never forbids, and refusing a dependency on a shelved *open* statement would be a
  rule about deps nothing else has. If the owner wants deps covered, it is one branch in
  `check_shelved`.
- The refusal reads the whole target (`load_target`) once per pull request, as the step-9
  settlement and the literature check already do; a tree that does not load refuses nothing
  here, since the check that reads it names the defect.
- `details["shelved"]` is the row object verbatim, so the service's 409 (T8) can carry the same
  shape.
