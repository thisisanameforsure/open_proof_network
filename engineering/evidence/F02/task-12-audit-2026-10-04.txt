What was wrong
  After F02-T11, four programs still elaborated a contributor's file in the process that prints the
  verdict, with initializers on: opn-witness-type (step 7: Witness.lean and each witness a partial
  carries), opn-used-constants (step 8: Proof.lean), opn-artifact-type (step 4's last word: a
  counterexample's or vacuity certificate's type) and opn-relation-type (admission: Relation.lean).
  #eval / run_cmd / macros / elaborators in the file ran there, after the nonce was read but in the
  same address space (T11's stated residual: /proc/self/mem, a thread printing into the capture).
  Steps 7 and 8 also read the staged copies under the work directory and had work/build on their
  LEAN_PATH, i.e. the tree the step-4 contributor compile can write (the T10 hole, still open there).

The design, per program: what is read, what is still elaborated, and from what
  New module gate/lean/OpnGate/Compiled.lean:
    readOlean   - a module's constants and import names from its olean (readModuleData), nothing run;
    replayInto  - a port of Lean 4.33 Lean/Replay.lean onto Environment.addDeclCore (doCheck): each
                  constant added through the kernel in dependency order, constructors/recursors
                  compared with what the kernel generates, unsafe/partial left out. Lean's own
                  Environment.replay answers a kernel environment the elaborator's find? cannot see
                  (shown below), hence the port;
    axiomsOf    - moved from AxiomsMain; localClosure/sameDeclaration/localMismatch - moved from
                  StatementMeaningMain (both programs now import Compiled; behaviour unchanged).
  Python, gate/opn_gate/judging.py:
    area()               a fresh <work>.judge/<name>, never touching step 4's judging directory;
    build_statements()   target defs + each node's Context.lean + Statement.lean from the files of
                         record, by calls writable only there;
    node_statement()     the node's own statement build, once per run, shared by the meaning guard,
                         the artifact check and step 7;
    header_imports(), with_header()
                         a file's header import lines blanked and the gate's imports put first on
                         line 1, so line numbers are kept;
    compile_contributed() the contributor's file compiled in a call whose only writable directory is
                         <area>/compile (holding a copy of the trusted build); only the module's own
                         olean, a regular file, is copied by name into <area>/contributed, which is
                         never on any LEAN_PATH and is read by the judge at its path.

  1. opn-used-constants (step 8). Reads Nodes.«id».Proof from judge.modules (replayed by step 4):
     importModules loadExts := false, initializers OFF; footprint = usedConstantsOwnedBy (the
     module's own constants are recursed through and reported module: null, as before); axioms by
     walk. Nothing elaborated, read-only mounts, no source argument. The --file form (initializers
     on) stays for statements of record only: products' library tags and the statement QA
     grounding; no gate step uses it.
  2. opn-witness-type (step 7: the node's witness and each carried hole witness). The statement is
     built from the node's own files in the judging directory (the node's own reuses step 4's
     judge.statement). Witness.lean is compiled apart as Nodes.«id».Witness with its header replaced
     by `import <Statement module>`; its own imports must be among the statement's (the rule the
     elaborating program enforced, now checked in Python with the same message and code). The
     program imports the Statement module WITH extensions (initializers on; only modules of record
     are imported: toolchain, Mathlib, target Defs, the node's Context and Statement, all built by
     the gate in the judging directory), then adds the witness olean's constants with replayInto.
     Expected type, Meta.isDefEq at both transparencies, collectAxioms and printing are the old
     code, unchanged, so verdicts and printed strings are identical. --statement/--witness are now
     refused by the program. Step 7 reads node.path's files, never the staged copies.
  3. opn-artifact-type, counterexample and vacuity (= F08-T29b). New --statement-olean form:
     initializers OFF; the statement's type from the trusted Statement olean; the artifact's module
     (replayed by step 4) imported loadExts := false; expected S / ¬S / ¬W (expectedWitnessType in
     MetaM over the constant table); matches = the kernel's defeq and no local-declaration mismatch
     (as opn-statement-meaning); axioms by walk. Types print without notations, as T28 accepted for
     opn-statement-meaning (they are for a refusal's reader).
  4. opn-relation-type (admission). Variant and root statements built from their files in the
     judging directory (a failing root Context is still relation-root-context, F08-Q13); Relation.lean
     compiled apart under the union of the three files' imports (a Nodes./Defs. import outside the
     statements' own is refused: nothing else is built there). The program imports that union (+Init)
     with extensions (modules of record only), takes each statement's type from its olean (or from
     the union environment when a Context restates it, F08-T15/T21), adds the relation's constants
     with replayInto; isDefEq and collectAxioms as before. The elaborating form stays only for the
     defect-claim exhibits (exhibits.py, F08-T17), which this task did not own: follow-up below.

  NOT converted, and why (precise remainder; proposed F02-T13)
  - opn-artifact-type for partial/reduction (hole extraction). holeReport needs, in one process,
    (a) the assembly's proof term (value? allowOpaque), (b) notations to print closed types
    (ppRoundTrippable), (c) the parser and term elaborator to read them back (reElaboratesTo,
    F07-R19), (d) isCasesOnRecursor (auxRecExt) and reducibility (structCases?, restatesGoal).
    (b)-(d) need extensions, and importing the contributor's module with extensions executes it
    (finalizeImport runs runInitAttrs). Design for T13: import with extensions only the assembly's
    non-contributor closure (Init, Mathlib, target Defs from the trusted build, the node's repo
    Context of signatures), then replayInto the contributor modules of the closure in dependency
    order (each dep's and use's Proof olean from judge.modules - a duplicate theorem against its
    signature is skipped as Lean's Replay skips it - then the assembly), and run holeReport
    unchanged on the replayed value. To settle with the real toolchain on a Mathlib target: a
    dep/use Proof importing a Mathlib module the statement does not (add every non-graph import of
    the closure to the import set); judge.modules' generated Context is contributor-compiled and
    must not be imported (use the repo Context); the siblings/ancestors probes are statement text
    and stay elaborated. Today the partial path is the elaborating program behind T11's nonce; the
    assembly's type is already guarded from compiled modules (T28), so what a forged report could
    still change is the hole list (names, closed types, defeq_goal/sibling/ancestor, roundtrip).
  - exhibits.py's circularity exhibit through opn-relation-type --relation <source>: convert the
    same way as admission (compile_contributed + the compiled form).
  - "Modules of record" for a proposal at admission include the proposal's own Statement.lean and
    Context.lean, which layout.parse_statement checks by regex only (other commands are allowed),
    so an initialize there runs in step 7's and the relation's judge, as it already runs in the
    statement compile and in opn-hazards (the stance T11 took). Proposed: admission refuses any
    command in a proposed Statement/Context but imports, open, namespace, doc comments and the
    theorem (owner's call; a protocol surface).
  - Residual for every judge (T10's, T11's and leanchecker's too): a contributor-produced .olean is
    read by Lean's olean loader, which trusts the file's format (compacted region, no validation).

Proposed Q entry (F02-Q?)
  The judges read compiled modules (T12; 2026-10-04; audit finding A). After T11 four programs still
  elaborated a contributor's file in the process that prints the verdict. Now a witness or a relation
  proof is compiled in a call of its own, writable only in a scratch area, under a header the gate
  writes, and the judging program reads its olean as data and adds its constants through the kernel
  into an environment imported only from modules of record, so printing and definitional equality
  are what they were; step 8's footprint and a counterexample's or vacuity certificate's type
  (F08-T29b) are read from the module step 4 replayed, imported without extensions. A partial's hole
  extraction still elaborates its assembly (T13 proposed), and so do the defect-claim exhibits
  (follow-up). Cost: one witness compile per gate run, about four more Mathlib imports per admitted
  variant.
