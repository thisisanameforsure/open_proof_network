The fix
  (a) Judging programs that read compiled modules execute nothing of them.
      Frontend.runMain gains `args` and `(initializers := true)`; opn-statement-meaning runs with
      initializers off and imports the artifact with loadExts := false (constants only: the
      kernel comparison needs nothing more; pretty-printing for a refusal may show fewer
      notations). Step 5 asks the new opn-axioms (gate/lean/OpnGate/AxiomsMain.lean, lakefile
      exe, Dockerfile check): initializers off, loadExts := false, axioms collected by walking
      the declaration's constants (types, values, constructors) through the constant table the
      replay re-checked, and the declaration must be declared by the named module.
      LocalToolchain.axioms calls it through the metaprogram runner; `scratch` is unused.
      With loadExts := false, Lean 4.33's finalizeImport does not call runInitAttrs at all, so
      no `initialize` runs even in a process whose flag is on (`lean --run` above).
  (b) Every metaprogram call carries a per-call nonce (secrets.token_hex(16)) written on stdin
      (`--nonce stdin`; SandboxToolchain creates the container --interactive and starts it
      attached to stdin only then). runMain reads it before importing or elaborating anything,
      runs the body with stdin/stdout/stderr isolated (IO.FS.withIsolatedStreams), prints a
      sentinel after the body returns, and emits only the line before the sentinel, as
      `@opn-verdict <nonce> <json>`; anything else captured goes to stderr. The parser accepts
      exactly one line with this call's tag. parse_axioms now answers None when more than one
      line names the declaration (it is no longer on the gate's path).

Why the nonce matters only once (a) holds, and what it buys before then
  A nonce proves a line came from code that knew it. Where no contributor code runs in the
  process (opn-statement-meaning, opn-axioms after (a)), nothing could forge a line anyway; the
  nonce is a second lock that keeps holding if (a) regresses. Where contributor code does run
  (the four elaborating programs), the nonce is read from stdin before that code starts and stdin
  is then an empty buffer, so the code cannot read it from stdin, argv or the environment; a
  forged line it prints to the real stdout is untagged, and one it prints to the captured stdout
  is not the line before the sentinel unless it runs after the body's own verdict. What remains:
  code that reads the process's own memory (/proc/self/mem) to find the nonce, or a thread it
  starts that prints into the capture between the verdict and the sentinel. That is why the
  conversion below is the real fix for those four.
