What was wrong
  After F02-T12, opn-artifact-type for a partial or a reduction still elaborated the contributor's
  assembly in the process that printed the hole report (`--artifact <work>/src/Nodes/<id>/Proof.lean`,
  with the work directory's build on its LEAN_PATH and its generated Context's imports, i.e. the deps'
  contributor-compiled Proof modules, imported with their extensions). Every command of the assembly
  took effect in that process, behind T11's nonce only. One forgery needs no nonce at all: an
  `@[app_unexpander]` (or a delaborator) is a function the contributor wrote, registered by an
  attribute, and the judge's pretty-printer runs it on every hole's type, so the assembly chose how its
  holes were printed (shown below at 4.33.1). Anything else elaborated there (#eval, run_cmd, a macro,
  an elaborator, an initializer of a module it imported) ran beside the report: the hole names, closed
  types, defeq_goal / defeq_sibling / defeq_ancestor and the round trip were all computed in a process
  the contributor shared. The sibling and ancestor probes were staged in the work directory.

The design (as proposed in T12's evidence, with one deviation, below)
  Lean (gate/lean/OpnGate/ArtifactTypeMain.lean, Compiled.lean, Holes.lean):
    graphClosure (Compiled.lean, new) - from the assembly's olean, walk its imports: every `Nodes.*`
        module is read by path from --modules (readOlean: constants and import names, nothing run);
        every other import is collected as external. Module after the modules it imports; start last.
    compiledHoleJudgment (ArtifactTypeMain.lean, new; `--statement-olean ... --kind partial|reduction
        --artifact-olean <judge>/modules/Nodes/<id>/Proof.olean --modules <judge>/modules`):
        importModules (Init + every external import of the closure: toolchain, Mathlib, the target's
        Defs.*) WITH extensions, from a LEAN_PATH whose only graph entry is the statement's own build
        in the judging directory (built from the record by judging.node_statement); then replayInto
        each graph module of the closure in dependency order (the deps' and uses' Proof modules, the
        generated Contexts, which hold no constants), refusing if any of them already declares the
        node's theorem; the sibling/ancestor probes (statement text of record) elaborated on that
        environment, exactly where the elaborating form elaborated them (on the assembly's imports);
        then replayInto the assembly, setMainModule to its module name, and the elaborating form's
        TermElabM block unchanged: expectedArtifactType, isDefEq at both transparencies,
        holeReport (value? allowOpaque := true; ppRoundTrippable with pp.coercions.types,
        pp.numericTypes, pp.funBinderTypes; reElaboratesTo), axioms by walk (axiomsOf). The
        statement's type is read from its trusted olean. Initializers are on (as for T12's witness
        form): only modules of record are imported.
    holeReport gains `foreign : NameSet := {}` (additive; the elaborating form passes nothing and is
        unchanged): see "What the replay does not carry".
  Python:
    toolchain.ArtifactRequest gains artifact_olean and modules (additive; the compiled form's args
        now also carry --siblings/--ancestors when given, which the hole-free kinds never are).
    steps/artifact.py: every artifact that reaches judge() goes through _run_compiled; for
        HOLE_KINDS it stages the probes in judging.area(work, "holes") and calls the program with
        read-only mounts [judge.modules, the statement build, the probes area], nothing writable,
        and LEAN_PATH = [the statement build] (never judge.modules).
    The elaborating form stays in the binary as the reference test_artifacts_lean.py's golden was
    made with (as T12 kept --file); no gate step calls it, and the module docstring says so.

  Deviation from the proposed design: the node's repo Context of signatures is NOT imported. The
  dep theorems come from the deps' Proof modules, replayed through the kernel, exactly as the
  generated Context gave them to the elaborating form. Importing the repo Context as well would make
  every dep theorem a duplicate that replayInto skips only when its type is structurally identical
  to the signature's; any elaboration difference between the Context's text and the dep's statement
  would then fail every partial on that node (fail closed, but a regression the old form did not
  have). Nothing the repo Context holds is needed: it has no extensions beyond signatures. The one
  behavioural consequence: holeReport's restsOnSorry now walks into dep proof values (they have no
  module index once replayed); a merged proof carries no sorryAx (step 5), so the answer is the same,
  at the cost of the walk.

What the replay does not carry (found by running it, not assumed)
  A replayed constant carries no extension entries: no instance, notation, simp, reducibility,
  unexpander/delaborator, matcher info. That is the point (an entry is the contributor's data, and some
  are the contributor's code). One case changed a printed type: a `match` in a hole's type is the
  assembly's own matcher (`OpnProp.and_swap_reassoc.match_1_1`), which without matcher info prints as
  that constant, and the constant exists in the judge, so the printed text READ BACK (closed_roundtrip
  true) - a child statement naming a constant that exists in no child's environment. Before T13 it
  printed as `match ... | n.succ => True` and did not read back. Fix: holeReport's `foreign` set (the
  assembly module's constants that are not the statement olean's) - a hole whose closed type uses one
  is closed_roundtrip false (and its expected_witness is withheld when that type uses one). The verdict
  is the old one (hole-not-roundtrip); only the printed text in details.unwritable differs. A hole whose
  printed type needs an instance or notation that a dep proof or the assembly declared does not read
  back and is refused the same way: fail closed, never a child written wrong. (`@[irreducible]` lost on
  an assembly-local def makes it unfoldable at default transparency: the offload rule can only find
  more restatements, never fewer.)

Proposed Q entry (F02-Q13)
  A partial's holes are read from compiled modules (T13; 2026-10-04; audit finding A, the remainder
  T12 left). Until now opn-artifact-type elaborated a partial's assembly in the process that printed
  its hole report, so the assembly's own code (an unexpander, a delaborator, an #eval, an initializer
  of a module it imported) ran there and could shape the holes: their names, their printed types,
  and the offload rule's answers. The program now imports with extensions only modules of record
  (Init, Mathlib, the target's definitions from the gate's own build), reads the assembly's olean and
  the graph modules it reaches as data from the judging directory, adds their constants through the
  kernel in dependency order, and runs the unchanged extraction on the replayed proof; the sibling and
  ancestor probes, statement text of record, are elaborated there as before. The node's repo Context
  is not imported: the dep theorems come from the deps' replayed proofs, as the generated Context gave
  them, so a signature that differs from its proof only in elaboration cannot fail a partial. A
  replayed constant carries no extension entries, so a hole whose type names one of the assembly's own
  constants (a match's matcher, a where-helper) is reported as no round trip and refused
  (hole-not-roundtrip), as a match hole already was; the five partial fixtures' reports are unchanged
  byte for byte. Cost: about one more kernel replay of the node's closure inside step 4.
