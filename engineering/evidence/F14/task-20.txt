F14-T20 — the gate admits every draft before any pull request opens
====================================================================

Why. T19's live probe used the hosted fast check (POST /check), which has a 20 s budget and reads
no committed defs/, so it could sample the port but not judge it (Q17). The judge is the gate's own
admission (R2) in the pinned step-3 image, which is what an intake pull request meets; for a bulk
load of a few hundred drafts it has to run before the pull requests, not as them.

What changed
  gate/tools/wave.py             writes <draft>/draft.json {key, target_id, file, defs, hazards}: one
                                 source for a draft's inputs (no tool parses import.sh).
  gate/tools/wave_admit.py       run: shard k/N of the drafts (id order), each imported into a scratch
                                 clone with `intake import-fc … --spec <live gate-spec> --sandbox
                                 --image <pinned>` (or --no-toolchain, the dry run), the CLI's own JSON
                                 kept per target, a shard summary; merge: the shards joined, REPORT.md
                                 (refusals by check, each named), import-admitted.sh = import.sh with
                                 only the admitted targets' lines, header verbatim.
  .github/workflows/wave-admit.yml  dispatch (min_score, keys, shards, spec_target): draft job (registry
                                 fetched at the catalog's pin, wave.py, artifact), N admit shards (graph
                                 cloned shallow as the scratch target, image pulled by the live spec's
                                 digest, wave_admit run), merge job (report artifact, 90 days). Read-only
                                 against every host; no secret.
