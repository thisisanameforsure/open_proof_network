2. The change
-------------
mcp/writes.py  RENAMES (read-only MappingProxyType) is the one rename map:
                 claim_node {ttl: ttl_hours}; propose_speculative_node {stmt: statement};
                 propose_variant {stmt: statement}; submit_proof {attestation: precheck_job_id}.
               present(tool, args, *names) sends each supplied argument under RENAMES[tool]'s
               field, or its own name; an omitted argument sends nothing. Every write handler
               (all thirteen) builds its body through it; the keyword renames that lived inside
               four handlers are gone.
               submit_proof: precheck_job_id is a declared string parameter, attestation is no
               longer required; exactly one of the two, otherwise an adapter error
               {error: arguments-invalid, message: "submit_proof takes exactly one of
               `attestation` (the get_precheck result) and `precheck_job_id` (its id); both
               were|neither was given", source: adapter}, raised before any endpoint call. The
               attestation form sends its id, so both forms send the same body. (Not a JSON
               Schema oneOf in the input schema: top-level oneOf is refused by some clients'
               tool-schema validators, and the message names the rule.)
mcp/reads.py   ONLY the TOOLS tuple (list_submissions registered after get_submission, no
               parameters) and list_submissions' docstring. FRONTIER_SCHEMA (frontier/v3 since
               F03-T7) untouched.
mcp/bijection.py  Row("list_submissions", "read", ("GET /submissions.json",), "GET /submissions.json").
mcp/schemas/list_submissions/v1.json  {snapshot_at, open: [submission]} with the submission
               definition copied from get_submission/v1.json's $defs, plus the error branch.
               The deploy check globs the directory against TOOLS; api-deploy.yml not edited.

5. Edge cases (new: api/tests/test_mcp_renames.py, 8 tests)
-----------------------------------------------------------
- submit_proof with both, and with neither: ToolError arguments-invalid, source adapter, the
  message names both arguments and says which case, the doc validates against
  mcp/submit_proof/v1, and no endpoint call was made (call.sent == []).
- submit_proof with an attestation lacking an id sends precheck_job_id null: the endpoint names
  that refusal, the adapter does not guess (F09-R7).
- An omitted renamed argument sends nothing, for every RENAMES entry but submit_proof's (whose
  omission is the both-or-neither rule): claim_node without ttl, propose_speculative_node and
  propose_variant without stmt — neither the argument nor its field in the body, and the body
  otherwise equals the arguments.
- submit_proof by precheck_job_id sends no attestation field.
- Every RENAMES entry names a parameter the tool declares, and renames it to something else.
