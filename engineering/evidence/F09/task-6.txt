2. The change
-------------
mcp/calls.py   Tool.write keeps one meaning — the tool changes state (readOnlyHint and
               idempotentHint false). Who may call it is a new field, Tool.access:
                 "anyone"   no bearer read or forwarded (every read; get_token)
                 "bearer"   refused without a verified bearer before the endpoint (the writes)
                 "endpoint" the bearer is forwarded when there is one and the endpoint decides
                            (precheck_submission; POST /precheck opens the tutorial node, F06-R2)
               A write defaults to "bearer" and a read to "anyone", so an anonymous write is
               always declared, never a default (C7); a read declared anything but "anyone" is
               a ValueError at import.
mcp/server.py  The bearer gate moved from writes.forward into call_tool, after argument
               validation: token = bearer() if tool.forwards_bearer; a tool that needs_bearer
               without one gets the unauthorized result and no HTTP client is even opened.
               INSTRUCTIONS name the two anonymous writes.
mcp/auth.py    UNAUTHORIZED is the route's shape: {"error": "unauthenticated", "message": "this
               tool needs `Authorization: Bearer <token>`. To mint one without leaving the MCP:
               run precheck_submission on the tutorial node with no token, poll get_precheck
               until it passes, then call get_token with proof {kind: tutorial, job_id, nonce}"}.
               The SDK's transport-level verifier and bearer backend are unchanged (F09-Q6).
mcp/writes.py  forward() no longer checks the token (the declaration does). precheck_submission
               is access="endpoint". New tools: get_token -> POST /tokens with {proof, pseudonym,
               dco} verbatim, access="anyone"; propose_witness -> POST /proposals/witness with
               {node_id, witness}, access defaulting to "bearer".
mcp/bijection.py  Rows get_token ("POST /tokens") and propose_witness ("POST /proposals/witness").
mcp/schemas    get_token/v1.json and propose_witness/v1.json: the write envelope schema, as
               claim_node's (the deploy check globs this directory against TOOLS; no edit to
               .github/workflows/api-deploy.yml needed).
api/tools/smoke_mcp.py  Still compares the exact refusal body (it imports auth.UNAUTHORIZED); its
               docstring and printed line now describe the route-shaped body naming get_token.

4. Pins rewritten, and why
--------------------------
api/tests/test_mcp_auth.py::test_token_required_for_writes_only
  pinned "every write refuses without a token". Two are anonymous by design now, so the test
  lists them (ANONYMOUS_WRITES = {get_token: anyone, precheck_submission: endpoint}) and asserts
  that set equals the declared one — a new write cannot become anonymous silently. Every other
  write is the unauthorized envelope with nothing stored, pushed or dispatched; the two listed
  ones reach their endpoint and get its own 400, not the adapter's 401. MINIMAL gains both tools.
api/tests/test_mcp_surface.py  WRITES gains get_token and propose_witness; the results-schema
  args map gains an argument set for each (both answered by the endpoint's refusal, validated).
api/tests/test_mcp_equivalence.py  WRITES gains propose_witness (setup: the hole add_hole seeds);
  get_token is its own block, because its proof is each twin harness's own anonymous tutorial job
  (a Setup has no precheck key); masked() now masks a "token" value beside the ULIDs.
api/tests/test_finding_mcp_bootstrap.py  the four strict xfail marks and their reason constants
  removed; the module docstring says so.

5. Edge cases (new: api/tests/test_mcp_bootstrap.py, 7 tests)
-------------------------------------------------------------
- get_token with a wrong nonce: the tool's refusal == POST /tokens' for the same body (400
  proof-invalid); the right nonce still mints afterwards.
- get_token with a used nonce: the second call's refusal == the HTTP path's third (400
  proof-invalid).
- get_token forwards no bearer: a caller already holding alice's token mints a new identity, and
  the returned token claims as the new pseudonym.
- precheck_submission with no token on a non-tutorial node: the route's own 401 body
  {"error": "unauthenticated", "message": "this route needs `Authorization: Bearer <token>`"}
  passed through (not the adapter's), equal to POST /precheck's, nothing dispatched.
- Anonymous tutorial precheck through the adapter == POST /precheck on a twin harness (job id and
  nonce masked), one dispatch each.
- propose_witness on a ready node (400 witness-not-missing) and on an unknown node (404
  node-unknown): the route's refusal, equal over both paths, nothing pushed.
