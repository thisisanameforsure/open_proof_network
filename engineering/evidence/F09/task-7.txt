5. Why list_submissions is built but not registered
---------------------------------------------------
test_mcp_surface.py::test_d28_rows_verbatim requires every bijection row's d28 cell to appear
verbatim in D-28 or D-35 of docs/architecture_decisions_v_3_12.html. No cell for
list_submissions exists there, and docs/ is held by another session. Registering the tool would
fail that test (make verify, the pre-commit hook) and weakening it is not allowed, so the handler
waits unregistered. The assertion that would go red on registration:
  assert wanted in d28 or wanted in d35, row   (row = Row("list_submissions", ...))
Row text to add to D-28's read-tool table (the F09-T6 notation-addendum shape):
  | list_submissions | every pull request the service opened that no live read has found merged
    or closed — id, node, target, kind, pull-request number and URL, pseudonym — the snapshot
    get_node filters per node | GET /submissions.json |
and, for get_submission's row, the Returns cell could name the live state:
  "status (the pull request's live checks, reviews and mergeability) and attestation ... —
   attestations/<id>.json + GET /submissions/<id>"
D-35's endpoint list would gain GET /submissions/<id> and GET /submissions.json as reads.
