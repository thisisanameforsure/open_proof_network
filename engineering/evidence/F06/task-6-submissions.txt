F06-T6, the submission half — POST /submissions refuses a node that turned blocked (2026-09-14)
===============================================================================================

The precheck half (engineering/evidence/F06/task-6.txt) made POST /precheck refuse a blocked node.
The plan's line for this half: "After their commit: the same call at submissions.py". The other
session's submissions.py work is on main, so the call lands here.

Worktree branch worktree-agent-a4bc9f319e9b10429, on main 800a08e (rebased after F03-T7 landed;
F07-T16's completion is 3f94711 beneath this commit).

Why a second call is needed at all: a precheck job outlives the state it was minted in. A job that
passed while the node was ready still binds a submission after a merge turns the node blocked, and
the submission then opens a pull request the gate can only refuse at the dependency check.

2. The change
-------------
api/opn_api/submissions.py post_submissions, directly after precheck.node_facts:
    precheck.check_open(ctx, node_id, facts)
The existing F06-T6 function, unchanged: only status blocked is refused, through the shared
precheck.blocked_error (F05-T9). So a proved node stays submittable (alternates, D-25 v3.13, and
the tutorial node's rehearsal, D-27), and a node the graph gives no status is not refused. It sits
before the bundle is validated and placed, before bound_job, and so before any push, pull request
or pending.record.
