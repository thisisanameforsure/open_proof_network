WHAT BLOCKS AC15
----------------
The App may not dispatch a workflow. Probed with a ref that does not exist, so no run was ever
created — a 403 means the permission is missing, a 422 "No ref found" would mean it is there:

  POST /repos/.../actions/workflows/precheck.yml/dispatches -> 403 Resource not accessible by
                                                                   integration

Granting `Actions: write` is the founder's act: a GitHub App permission change must be made on
the App and then approved on each installation. It cannot be done from a build session.

TO CLOSE AC15 (in this order)
-----------------------------
1. GitHub App `open-proof-network` -> Permissions -> Repository -> **Actions: Read and write**.
   Save, then approve the request on the installation (GitHub emails a link; it is also under
   Settings -> Applications -> Installed GitHub Apps -> Configure).
   Re-probe with the ref that does not exist; a 422 "No ref found" means it is granted:
     set -a; . ./.env; set +a
     uv run python - <<'PY'
     import sys; sys.path.insert(0, "api")
     import httpx
     from opn_api import config, githost
     R = "thisisanameforsure/open_proof_network_precheck"
     s = config.load()
     h = githost.HttpxGitHost(client_id="", client_secret="",
                              app_id=s.github_app_id or "", private_key=s.github_private_key or "")
     t = h._installation_token(R)
     r = httpx.post(f"https://api.github.com/repos/{R}/actions/workflows/precheck.yml/dispatches",
                    headers={"Authorization": f"Bearer {t}", "Accept": "application/vnd.github+json"},
                    json={"ref": "job/deliberately-absent", "inputs": {"job_id": "probe"}})
     print(r.status_code, r.json().get("message") if r.content else "")
     PY

2. Push main. The api-deploy workflow packages and deploys the function; its own post-deploy
   check is read-only, so nothing about the precheck path is exercised by the deploy itself.

3. Run the criterion's command:
     uv run python api/tools/smoke_precheck.py https://api.openproofnetwork.org
   It takes no account and no token: it reads the graph, finds the tutorial node, sends that
   node's own committed proof anonymously, waits for the run, exchanges the nonce for a token,
   uses the token on a write route, and checks the nonce is refused a second time. It prints the
   latency of each state change — that is the Stage 0 series §6 asks to be recorded here.

4. Append its output to this file and mark T5 done in the spec and in specs/index.html.

WHY MAIN WAS NOT PUSHED TONIGHT
--------------------------------
Pushing main deploys. Deploying before step 1 would put a POST /precheck on the live service that
answers 502 for every caller — worse than today's, which accepts a job and never runs it. The
permission and the deploy belong in the same sitting, and the permission is the founder's.
