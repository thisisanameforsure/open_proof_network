WHAT BLOCKS AC15
----------------
The App may not dispatch a workflow. Probed with a ref that does not exist, so no run was ever
created — a 403 means the permission is missing, a 422 "No ref found" would mean it is there:

  POST /repos/.../actions/workflows/precheck.yml/dispatches -> 403 Resource not accessible by
                                                                   integration

Granting `Actions: write` is the founder's act: a GitHub App permission change must be made on
the App and then approved on each installation. It cannot be done from a build session.

WHY THE RE-PIN TOOK TWO COMMITS
-------------------------------
A precheck job pins frontier.json's rendered_from, not the graph's main (F06-Q10), checks
the graph out at that commit, and reads the network pin from *that* checkout. Re-pinning
main alone would therefore never have reached the job: rendered_from still named b0f82fe9,
whose gate-spec.json holds the old pin. So the pin landed first and the products were
rendered from it second, which is the two-commit shape the log records for pin work.
