D-19 closes here: the account-free path end to end
--------------------------------------------------
The whole loop now runs against the fakes, in one test (AC10), with no GitHub account anywhere
in it:

  POST /precheck  {node_id: tutorial-and-swap, bundle: {...}}   no Authorization header
    -> 202 {id, nonce, authenticated: false, public: true}
  (the scratch repo's run completes; its result is signed by the precheck key)
  POST /tokens    {proof: {kind: tutorial, job_id, nonce}, pseudonym, dco}
    -> 201 {token, identity: {proof_kind: "tutorial", pseudonym: "anon-p", ...}}
  POST /claims    {node_id: and-reassoc}   Authorization: Bearer <that token>
    -> 201

The last step is the one that matters: the token is not a trophy, it authenticates a write
route, which is what D-19 promised someone with no GitHub account.

AC10 — single use:
  a second exchange of the same {job_id, nonce} -> 400 proof-invalid, and the store still holds
  exactly one identity. Two mechanisms hold that line, not one: the nonce is marked consumed on
  the job, and the job id is the identity's proof_reference, so the store's own uniqueness rule
  would refuse a second identity even if the nonce check were bypassed.

AC11 — every other condition is the same 400:
  failing job (verdict fail, job done)      -> 400 proof-invalid
  passing job that was authenticated        -> 400 proof-invalid  (and it never had a nonce, R2)
  right job, wrong nonce                    -> 400 proof-invalid
  right job, no nonce                       -> 400 proof-invalid
  unknown job id                            -> 400 proof-invalid
  no job id                                 -> 400 proof-invalid
  unfinished job (run still in progress)    -> 400 proof-invalid
  None of them mints an identity, and none of them spends the nonce: the real exchange still
  works afterwards. An unauthenticated caller cannot probe for which condition failed (R7).

Two judgment calls made here, recorded in the spec as Q8 and Q9:

  Q8 — the exchange advances the job rather than requiring a prior poll. An agent that posted a
  bundle and waited need not remember to call GET /precheck/<id> before spending its nonce; the
  exchange calls the same `precheck.advance` the GET does. It is no new exposure, because GET
  /precheck/<id> is itself unauthenticated (R5), and it removes a step an agent could get wrong.

  Q9 — the exchange is address-limited by the same counter as GET /auth/github/start
  (OPN_API_TOKEN_STARTS_PER_DAY, default 10). Both answer the same question — how many identities
  may one address try to mint in a day — and POST /tokens is otherwise the one route with no
  identity to limit by. The honest flow costs one: precheck, then exchange.

A pseudonym clash does not burn the nonce (test_a_pseudonym_clash_does_not_burn_the_nonce): the
409 is retryable with another name, which is the rule F05-AC3 already set for the GitHub proof.
Both proof kinds now reach issuance through one path with one undo, so the two cannot drift.
