F06-T20 — products-pending says its wait in the body; a merged partial waits on products until its holes render (bug B8, agent run 2026-11-19)
==================================================================================================================================================

Finding
-------
B8 (3 agents): `409 products-pending` carried `Retry-After: 240` as a header only, so an agent
reading the JSON body (every MCP client, most HTTP ones) polled blindly. Agent 9: GET
/submissions/<id> read `waiting_on: None` for a merged partial while its new holes still answered
`products-pending` to a claim.

How waiting_on is derived (read first): `pending.answer` -> `reconcile` (host state; a merged pull
request's own `waiting_on` is null) -> `waiting_on_products`, which set `"products"` only for a
proposal whose node is unrendered, a merged annex the products' commit lacks, and a merged witness
whose node still reads witness-missing; plus `answer` itself sets it while an attesting kind has no
attestation yet. A partial whose attestation had landed matched none of these, so it read null even
though its hole children were not yet in graph.json.

Every products-pending refusal (grep of api/opn_api): pending.unknown_node (merged proposal / hole
child), precheck.awaits_render (merged witness, merged annex; called from precheck and claims),
precheck.job_commit (F06-T18, nodes changed after the products commit), precheck.carried_commit
(F06-T14, hole not in rendered_from). store.py has none.

Fix
---
* api/opn_api/pending.py: `products_pending(ctx, message, details)` builds every
  `409 products-pending`: `Retry-After` header and `details.retry_after_s` (both
  PRODUCTS_RETRY_AFTER_S), and `details.graph_commit` = `ctx.head`, main's commit the service
  read the products at, null if it never learned one (not invented). A refusal that already names
  the commit it was judged against keeps it (F06-T18's products commit, F06-T14's rendered_from).
  All five sites use it (`awaits_render` now takes `ctx`; its two callers in precheck and one in
  claims pass it).
* `waiting_on_products`: a merged record with `expected_nodes` (a partial's new holes, F06-T15)
  waits on `"products"` while any of them is missing from `precheck.graph_doc` (the products the
  service reads) — `_holes_unrendered`. The service already used the same vocabulary
  (`WAITING_ON_PRODUCTS = "products"`).
* gate/agents/AGENTS.md: one paragraph after "never the 404 node-unknown a mistyped id gets" on
  `details.retry_after_s`, `details.graph_commit`, and a partial's `waiting_on: products`.
