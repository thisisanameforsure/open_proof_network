## green

What changed (api only; no schema change, since a receipt is not a product and claims.json stays
claims/v1):
- api/opn_api/claims.py: `held_on` (the caller's active claim on this node of this target) is
  checked before the cap, and a repeat answers 200 with that claim unchanged; `others` (the node's
  other active holders, pseudonym and expires, the registry's order) rides on every POST /claims
  receipt; `get_my_claims` serves GET /claims/mine.
- api/opn_api/routes.py: GET /claims/mine, authenticated, no D-35 row (a read, like
  /checks/{check_id}), with its purpose line for GET /.
- api/opn_api/mcp/reads.py, calls.py, server.py, bijection.py, schemas/list_my_claims/v1.json:
  the list_my_claims tool. It is a read declared `bearer`; `Tool` now allows that for a read (it
  still refuses `endpoint`), and the server refuses a bearer-less call to it in the read tools'
  error shape ({error: unauthenticated, message, source: adapter, status: 401}) rather than a
  write's envelope. claim_node's description says a repeat returns the same claim and to read
  `others`.
- docs/architecture_decisions.html: D-28's read table gains the list_my_claims row with a
  notation note of 2026-09-24 (the bijection test quotes D-28 verbatim, and a new read tool has
  no row otherwise). No decision changes.

Existing tests that had pinned the old behaviour, restated to the rule they were about (none
deleted): test_claims.py::test_ttl_caps (releases between claims), ::test_active_claim_cap and
::test_cap_is_per_identity (the capped claim is on the fixture's other claimable node, cap 1),
test_rejections_claims.py::test_expired_claims_do_not_count_toward_the_active_cap (idem),
test_ratelimit.py::test_hourly_write_limit (a repeat is 200 and still charged as a write).
test_mcp_surface.py READS gains list_my_claims; test_mcp_equivalence.py's AC3 test compares
list_my_claims to GET /claims/mine.
