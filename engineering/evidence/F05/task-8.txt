2. The change
-------------
api/opn_api/identity.py, implemented once:
  _parse_body(request)            the old body_fields, unchanged: JSON, or a urlencoded form nested
                                  so proof.id is proof and dco.accepted is a boolean.
  refuse_unknown(fields, accepted) 400 unknown-field naming every stray top-level key, sorted, and
                                  listing the accepted ones; details {unknown, accepted}.
  body_fields(request, accepted)  parse, then refuse; the allowlist is a required argument, so a
                                  body-taking handler cannot omit it (mypy --strict holds that).
  Only top-level keys are refused. Keys inside a field's object are that field's business
  (check_tooling keeps its three names; records are schema-validated). Forms get the same rule
  after nesting. An empty body is {} and has no stray key.
Each handler passes its allowlist, a module constant beside it:
  identity.TOKEN_FIELDS         proof, pseudonym, dco
  claims.CLAIM_FIELDS           node_id, target_id, ttl_hours
  precheck.PRECHECK_FIELDS      node_id, bundle
  submissions.SUBMISSION_FIELDS node_id, artifact_type, bundle, tooling, precheck_job_id
  appends.POSTMORTEM_FIELDS     node_id, yaml
  appends.ANNEX_FIELDS          node_id, text, licence, model_and_tooling
  appends.APPROACH_FIELDS       target_id, record
  requests.REVISION_FIELDS      node_id, defect_class, evidence
  requests.DEFECT_FIELDS        stmt_ref, class, line, exhibit
  proposals.SPECULATIVE_FIELDS  target_id, statement, witness, deps, model
  proposals.VARIANT_FIELDS      the same plus relation, relation_proof
  proposals.WITNESS_FIELDS      node_id, witness
Each list is exactly what the handler reads (checked against every fields.get in the module).
The refusal runs as the handler's first body read: before a token proof is spent, a rate limit
charged, a job created or a branch pushed.
Checked against every client in the repo before landing: the MCP write tools' present(...) key
lists (mcp/writes.py), the bodies gate/agents/AGENTS.md executes against the fake service
(precheck, token, claim, submission, postmortem, annex, proposal), the token form's hidden fields,
and api/tools/smoke*.py bodies. All use only allowlisted keys.
The edits were one script asserting each replacement's count (the 2026-09-09 log lesson), then
ruff format for quote style.

3. Existing tests that pinned old behaviour
-------------------------------------------
api/tests/test_body_cap.py::test_a_body_exactly_at_the_cap_is_parsed
  failed with: assert 'unknown-field' == 'pseudonym-invalid'
  Its padded_json filled the body with a "pad" key that no route defines, and asserted that the
  parser answered pseudonym-invalid (proof the body reached the parser). "pad" is now correctly an
  unknown field. The test is about the cap, not about stray keys, so the padding moved into a
  field POST /tokens reads (a 47-character pseudonym, past the 39 allowed) and the assertion is
  unchanged. The 413 test that shares the helper is unaffected (refused before parsing).
test_finding_unknown_fields.py: the two strict xfail marks removed (every write route, and the
tester's precheck key); no assertion edited; the module docstring says the marks came off.
