F05-T25 (audit 2026-10-04): info/v2 names the contributor guide and the error-code catalog
=========================================================================================

Finding: info.json (D-28 server_info) told an arriving agent the protocol version, the schemas
and the rate limits, and not where the guide is or where an error code is explained. Owner
approved the bump (sign-off S4).

Where the URLs come from (read first): info.json is the graph's product, rendered by the gate
(products.info_doc) in the post-merge job, and the service serves it with rate_limit_policy filled
from its configuration (api/opn_api/info.py). The gate has no configuration for where the service
or the guide is deployed, and the products must regenerate byte for byte from the tree (F03-R11,
check_products.py), so the committed file carries null for both and the SERVICE fills them on
every read, exactly as it fills rate_limit_policy:
  errors_url = OPN_API_PUBLIC_URL + "/errors.json"   (existing config input; the route is F05-T23's)
  guide_url  = OPN_API_GUIDE_URL                     (NEW config input, api/opn_api/config.py)
               default: <graph host>/<OPN_API_GRAPH_REPO>/blob/<OPN_API_GRAPH_BRANCH>/AGENTS.md,
               the same URL GET / already named (index.py now reads Settings.guide_url, so the two
               cannot disagree). No deployment hostname is written into code.
  A v1 document is served as v1 (no fields added; D-34, consumers parse by version).
