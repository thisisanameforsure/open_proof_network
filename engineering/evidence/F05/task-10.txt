== 2. The change ==
api/opn_api/frontier.py
  - INFO_PATH = "info.json" is the generation marker.
  - committed(ctx, path): for any path but info.json, generation(ctx) runs first. When info.json's
    own revalidation returns a 200 whose ETag differs from the one held, stale_all_but() ages every
    other ctx.files entry to now - (window + 1) (relative to now, never 0.0: time.monotonic()
    counts from boot), so each revalidates by its own ETag on next use (a 304 keeps its body).
  - generation(ctx) is committed(ctx, INFO_PATH) with ApiError suppressed: an unreadable marker
    (unreachable host, or a graph with no info.json) invalidates nothing and the file being read
    decides for itself, serving its last good copy (C7).
  - info.json is its own marker, so GET /info.json still costs one fetch per window, not two.
api/opn_api/mcp/reads.py
  - committed() calls frontier.generation(ctx) first; nothing else changed.
No config change, no schema change, app.py untouched.

== 8. Residual, by design ==
- A file first fetched during a window can lead info.json by up to one window (it reads main
  as it is now while the marker still holds the older ETag). The finding was the opposite —
  a reader behind info.json — and that can no longer happen: info.json only moves through a 200,
  which ages every other entry at the same moment.
- A graph with no info.json costs one 404 fetch of info.json per request (the marker is never
  cached). Every graph renders info.json (F03), so this is not a live cost.
