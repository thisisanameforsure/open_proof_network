Harnesses: Who Proves Through the Network, and What a Connector Must Carry

Which proving harnesses contributors actually use as of September 2026. Part 1 covers hobbyist coding agents (weighted most). Part 2 covers hosted and self-run automated provers. Part 3 briefly covers orchestrating research harnesses. For each, the note sets out what a connector to the network's git, HTTP and MCP surfaces must contain, and closes with recommendations and how to test them. Evidence first, then a plan. It makes no decisions.

§0Summary

Most contributors will arrive through three coding agents: Claude Code, Codex CLI and Gemini CLI. Copilot and Cursor come next. Every major harness now connects natively to a remote streamable-HTTP MCP server, so the network's endpoint needs no bridge anywhere. A connector's real content is therefore not transport. It is five smaller things:

  • the config key and file name;
  • the placeholder syntax for secrets;
  • which instruction file the harness reads;
  • how headless mode approves an MCP call (every headless mode denies an unapproved call rather than prompting);
  • the client's limits on names, schemas, result size and timeouts.

Harnesses also leave the Lean version to the contributor. That is the largest correctness risk for hobbyists: a local project off the gate's Lean or Mathlib pin passes locally and fails the gate.

Aristotle is the only hosted prover an outsider can drive programmatically. The strong open-weight provers were trained on Lean 4.9, about two years behind the network's 4.33.1. Seed-Prover, AlphaProof Nexus, AxiomProver and Astra publish results but offer no API. A prover connector's substance is statement preservation, version probing and a verdict taken from the gate.

Orchestrators already use the network's own shape. They have converged on Lean declarations with sorry bodies and declared dependency edges, which maps almost one to one onto the network's nodes and holes.

§1Who actually proves, and with what

No survey or count exists of which harness Lean hobbyists use. primary Four proxies agree on the ranking.

  1. Tao's wiki of AI contributions to Erdős problems (Oct 2025 to Jun 2026) names models more often than harnesses. Its approximate counts: GPT variants 200+, Aristotle 150+ (mostly formalization), Claude 80+, Gemini 70+, Codex 30+. "Claude Code" is named for problem 696, and no Cursor or second-tier harness appears. summariser counts The counts were extracted by an automated summariser, not by hand.
  2. Official Lean tooling targets. The leanprover/skills pack supports exactly Claude Code, Gemini CLI and Codex CLI. cameronfreer/lean4-skills (about 448 stars) ships native plugins for Claude Code and Codex, and documents Gemini CLI, Cursor, Windsurf, Copilot, Antigravity and OpenCode. primary
  3. Tao's Claude Code formalization video. The first attempt took 45 minutes and crashed on its token budget. A decomposed second attempt took 25 minutes. snippet
  4. The network's own record. Every tester run from 2026-09-12 to 2026-09-23 used Claude agents. Claude Code was an MCP client of the service through claude mcp add --transport http on 2026-09-11 (repo log).

inference The ranking follows:

  • Ship first: Claude Code, Codex CLI and Gemini CLI.
  • Second: Copilot (VS Code and CLI) and Cursor.
  • Document cheaply: the second tier.
  • Treat specially: Mistral Vibe with Leanstral. It is the only Lean-specialised harness with a vendor behind it, and it was trained around lean-lsp-mcp. snippet

2.2 What the connector must carry

Transport is solved; do not build for it. primary No surveyed harness needs mcp-remote. Codex has no SSE variant at all. The server must therefore keep answering plain streamable-HTTP POSTs and never lean on an SSE fallback.

The bearer is the hard part. inference The network's write tools read the token from the HTTP Authorization header only (api/opn_api/mcp/auth.py; corrected 2026-09-24, as a draft of this note said it was a tool argument). Each harness spells a header from the environment differently: ${VAR} (Claude), ${env:VAR} (Cursor), ${input:id} (VS Code), bearer_token_env_var (Codex), and undocumented for Gemini's headers. Cursor reportedly drops mcp.json headers on tools/call over streamable HTTP. The token is also minted inside a session (get_token), while most harnesses read headers only at startup. Ship the unauthenticated snippet everywhere, add a header form where the harness supports one, and measure the restart cost per harness. If it is high, a token accepted as a tool argument is the fix, and that is an amendment to D-28, recorded as F16-Q3.

One file reaches three harnesses. A committed .mcp.json with {"mcpServers":{"opn":{"type":"http","url":…}}} is read by Claude Code, Copilot CLI and VS Code (its portable format). Codex, Gemini and Cursor each need their own file. Gemini's httpUrl/url distinction is the likeliest copy-paste error.

Instruction file. inference Use AGENTS.md as the single source, add a CLAUDE.md containing @AGENTS.md, and point Gemini at it with context.fileName. That covers all five harnesses without duplicated text.

Tool annotations are part of the connector. primary Codex decides approval from MCP annotations:

  • A call needs approval if destructiveHint is true.
  • It needs no approval if readOnlyHint is true.
  • Otherwise it needs approval whenever destructiveHint is unset or openWorldHint is unset or true.

Every read tool needs readOnlyHint: true to run under codex exec with no configuration. A snippet that writes must opt in to approval explicitly.

Limits set the tool surface. inference

  • Name the server opn.
  • Keep tool names short and lower-case, so that mcp_opn_<tool> stays under Gemini's 63 characters.
  • Stay well under 40 tools, for Cursor.
  • Keep results under about 10k tokens, for Claude.
  • Never rely on additionalProperties: false or anyOf defaults for correctness, because Gemini strips them. $ref support is documented by no harness.

A tutorial precheck took 138 s in the repo's log. That passes Claude's 2-minute foreground threshold into a background task and sits inside Codex's 300 s default. Longer operations need a poll-style tool.

Lean tooling is the contributor's, and the version is the risk. The typical stack is a coding agent, the local stdio server lean-lsp-mcp, and a skill pack. lean-lsp-mcp has about 517 stars and 23 tools: goals, diagnostics, lean_multi_attempt, lean_verify, and wrappers for LeanSearch, Loogle, Lean Finder, state search and hammer premise. primary It states no Lean version of its own and uses whatever the local project pins. inference So a hobbyist needs a project at Lean 4.33.1 and the graph's exact Mathlib commit. That means a 6.8–7 GiB checkout (repo log), or local checks disagree with the gate.

AXLE (https://mcp.axiommath.ai/mcp, free key, bearer) is the only third-party remote Lean MCP found, and it hosts lean-4.33.1. But every AXLE environment imports only import Mathlib at an unexposed revision. primary, live probe It cannot see the network's Defs/Context modules unless they are inlined, so it is a filter, not a verdict.

3.2 What the connector must carry

Aristotle packaging. inference Build a minimal Lake project containing:

  • lean-toolchain set to leanprover/lean4:v4.33.1;
  • a lakefile that requires Mathlib at the pinned commit;
  • Context.lean and any Defs/*.lean it imports, under their module paths;
  • Statement.lean as the work file.

Alternatively, inline everything into one self-contained file. Submit with the prompt "fill the sorry; do not modify the statement or imports", and disable agent questions for unattended runs. The prompt is free text, so the adapter must byte-compare the returned statement and header with the node's before any submission, because a proof may not add an import (F00-R19). It must also reject sorry, admit or a new axiom. Treat COMPLETE_WITH_ERRORS as a candidate partial, and OUT_OF_BUDGET and FAILED as a clean miss. Record the server's toolchain from GET /version. Poll with backoff, and never outlive the claim.

Open-weight adapter. inference One prompt template covers DeepSeek-V2, Goedel-V2 and Pythagoras. The loop is:

  1. Render the network header, Context and Statement as formal_statement.
  2. Sample through an OpenAI-compatible endpoint.
  3. Take the last lean block and splice only the proof body into the node.
  4. Discard the models' habitual import Aesop and open BigOperators Real Nat Topology Rat headers.
  5. Allow up to two Goedel-style repair rounds that feed compiler errors back.

Verify in the gate's own image, not in a hand-pinned stack. leanprover-community/repl has v4.33.0 and v4.34.0 tags but no v4.33.1, and LeanInteract claims support only up to v4.32.0-rc1. primary

Expect drift, and measure it. Fixed-snapshot provers are called brittle to Mathlib renames snippet, but nobody has published a before-and-after at a newer toolchain. Headline scores also rest on large budgets, such as Pythagoras's 93/657 on PutnamBench at pass@2048. A single local sample will do far worse.

Strength indicators for choosing a baseline, not a ranking
  • Aristotle: IMO-level results. It produced the Lean proof of Erdős #728 on 2026-01-06, the first Erdős problem regarded as resolved autonomously by AI. LeanMarathon reports Aristotle failing both of its 2026 papers after 40 h.
  • Seed-Prover 1.5: 88% on PutnamBench and 11 of 12 Putnam 2025 problems.
  • AlphaProof Nexus: 9 of 353 open Erdős problems and 44 of 492 OEIS conjectures. snippet
  • Leanstral 1.5: 587/672 on PutnamBench. snippet
  • Goedel-Prover-V2 32B: 88.0% on miniF2F at pass@32, rising to 90.4% with self-correction.

The network's own calibration run on 2026-09-17 produced three partials and no proof from three fresh agents. Aristotle is the natural first external baseline on those same targets.

Scale. LeanMarathon formalized all seven target theorems (258 lemmas) of two 2026 Erdős papers for $189–$624 per paper. primary That is formalization of existing papers, not discovery.

Export is mechanical. inference Concatenate the Statements in topological order. Tag each with @[blueprint "<node-id>"] and a sorry_using body. Put defs/ in as global context and merge the imports into one header.

Import needs more. inference It needs:

  • an id mapping table;
  • the network's own admission on every harness-invented node;
  • round-trip elaboration of every imported statement, because the repo log records gate-written holes whose coercions were lost in printing;
  • a D-8 revision, never an in-place edit, for any statement change;
  • a failure field distinguishing counterexample, misformalized and exhausted, if LeanMarathon's issues are to become postmortems or D-16 defect claims;
  • provenance for each import: harness, commit, model and cost.

§5Recommendations for connectors

The order follows the question's weighting:

  • snippets for the harnesses people use;
  • the server properties those snippets depend on;
  • the environment pin that makes local Lean agree with the gate;
  • then provers;
  • then orchestrators.

C1Tier-one snippets: Claude Code, Codex CLI, Gemini CLI

contains URL entry, approval, instruction file, timeouts

  • Claude: claude mcp add --transport http opn <url>, plus a committed .mcp.json with an explicit "type":"http". The type must be there, because an entry without it is silently skipped.
  • Codex: [mcp_servers.opn] url = …, default_tools_approval_mode = "approve" (or per-tool approval on the write tools), required = true, and tool_timeout_sec if any call can exceed 300 s.
  • Gemini: httpUrl, server name opn, "trust": true or a user policy file, and context.fileName including AGENTS.md.

C2Tier-two snippets: Copilot (VS Code and CLI) and Cursor

  • Copilot: the same .mcp.json serves Copilot CLI and VS Code's portable format. Also show VS Code's servers form.
  • Cursor: .cursor/mcp.json with url, and --allow-tool='opn' / --approve-mcps --force for headless runs.

Mark the Cursor snippet provisional until it is checked against cursor.com.

C3Server properties the snippets rely on

  • readOnlyHint: true on every read tool.
  • Explicit destructiveHint and openWorldHint on writes.
  • A tool count well under 40.
  • Short [a-z_] names.
  • Self-contained schemas that stay correct after Gemini strips additionalProperties and anyOf defaults.
  • Results under about 10k tokens.
  • A poll-style shape for any operation that can exceed about 2 minutes.
  • Streamable HTTP only, with no dependence on SSE.

C4Publish the environment pin

Expose the exact lean-toolchain (4.33.1), the graph's Mathlib commit and a ready lakefile, so a lean-lsp-mcp project matches the gate. State plainly that AXLE's lean-4.33.1 is import Mathlib at an unexposed revision: a fast filter, not the verdict.

C5One instruction source

Use AGENTS.md, with a one-line CLAUDE.md (@AGENTS.md) and a Gemini context.fileName entry. Document the second tier's key names, and say that Aider cannot connect over MCP.

C6Aristotle adapter

Everything in §3.2: packaging at 4.33.1, the version probe, disabled questions, asynchronous polling within the claim window, a byte-compare of statement and header, rejection of sorry, admit and new axioms, an optional AXLE check/repair_proofs pre-filter, and the gate precheck as the verdict.

C7Open-weight adapter

The DeepSeek/Goedel template, last-block extraction, a splice of the proof body only, two repair rounds, and verification in the gate image. Leanstral users connect instead through the MCP surface plus lean-lsp-mcp.

C8Blueprint bridge (later)

LeanArchitect @[blueprint] and sorry_using as the exchange format, with admission and round-trip elaboration on import, and provenance recorded.

§6How to test them

  1. A headless matrix against the fake service. Every harness accepts an http://localhost:PORT/mcp URL, so the repo's fake service can stand in. Run claude -p, codex exec, gemini -p, copilot -p and, once verified, agent -p, each with its shipped snippet unmodified. Assert from the service's own log that one read and one write were actually called. Assert on Claude's mcp_server_errors and Codex's required. Never assert on exit 0, which a skipped server also returns.
  2. A static contract test over tools/list. Check annotations, name length with the mcp_opn_ prefix (≤ 63 characters), tool count, and the absence of $ref and of correctness-bearing additionalProperties or anyOf defaults. Add a size test on the largest real results.
  3. Client-bug regressions. Probe Cline with type omitted (the SSE default), Kiro against a stateless server (issue #9553), Goose's protocol-version negotiation (#12257), and Cursor header forwarding.
  4. Pin agreement. Test that the published toolchain and Mathlib equal gate-spec.json. Run a scheduled probe of AXLE's environment list, keeping the output as evidence, as on 2026-09-17.
  5. Prover adapters offline. Build a fake of Aristotle's five v3 endpoints (POST /project, GET /project/{id}, /tasks, /result, /version) with aristotlelib==2.1.0 pinned. Add a test that a returned file with an edited statement or an added import is refused. For the open-weight adapter, use fixture nodes with known proofs.
  6. Live baselines. Run Aristotle on the three calibration targets, and run one drift measurement: the same open model on ported miniF2F statements at 4.9 and at 4.33.1.

Cost: the blocker for an automated harness matrix is model authentication, not MCP. §2's collapsed note lists the headless credential for each harness.
