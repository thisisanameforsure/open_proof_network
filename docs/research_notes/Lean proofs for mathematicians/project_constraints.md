## Q1. What the static site currently renders for a node, proof, statement, informal statement, and the graph/skeleton/hole views

### Takeaway
The site shows Lean verbatim (statement and attested `Proof.lean` text in `<pre class="lean">`, escaped, no highlighting or prose), plus an informal statement only at **target** level (from the curated `target.yaml` `informal:` field, KaTeX-rendered inside `.math`). Per-node prose exists only as an "Explainer" slot (human-submitted, labelled unverified), and **zero explainers and zero write-ups exist on the live graph**. There is no blueprint view; the DAG is an inline SVG of status-coloured pills.

### Cited Findings
- Node page template order is: id, status, wayfinding, claimability, `<pre class="lean statement">` statement, deps/origin line, **Proof**, trust flag, **Witness**, **Attestation** + alternates, **Attempts** (count, refuted routes, failure-class histogram), partials, **Explainer**, **Annex**, acknowledgments — [site/opn_site/templates/node.html](site/opn_site/templates/node.html)
- Proof section: for a `proved` node it prints "Proof merged in commit …", a link to the file, then the full Lean text in a `<figure class="artifact"><pre class="lean">` with a caption stating its sha256 equals the attestation's `artifact_hash`; if the bytes do not match the attested hash the text is withheld (F04 Q17). Otherwise "No proof merged yet." — [site/opn_site/render.py](site/opn_site/render.py) `node()` ~L1837–1877 and `lean_artifact()` ~L2238–2251
- A `native_decide` proof gets a flag: "its trust base is the compiler, not the kernel (D-4)" — render.py `node()` ~L1881–1885
- Explainer slot: if an explainer exists it is shown as `vouched_lines` (one line per valid signature) above an `untrusted_block("unverified", …, what="explainer")`; if none and node proved: "No explainer yet. A plain-language account of this proof, labelled unverified, is the next thing a writer could add, by pull request (D-3, D-36…)"; if unproved: explains an explainer needs a merged proof — render.py `explainer_block()` ~L1952–1970

- Informal statement (target level only): `inline_statement()` allows `code`, **strong**, *em*, links only to URLs a validated record already cites (R13), and passes `$…$`/`$$…$$` through escaped for KaTeX — prose.py L60–100; `informal_line()` / `informal_words()` read `tv.record["informal"]` or `["paraphrase"]` — render.py ~L904–910, ~L1134–1153

### Inferences
- A translator's natural slot on the node page is either (a) the existing Explainer slot (must be labelled unverified, carries author/model/date front matter, rendered by the deliberately tiny `prose.render` that has no math support), or (b) a new generated block, which would need a decision (see Q2). Today an explainer containing TeX would display raw `$…$`, because `.math` is applied only to the target's informal statement.
- Any rendering library must be vendored and same-origin (KaTeX precedent: sha256 manifest plus a test); no CDN, no server-side code, no runtime fetches.

## Q2. Protocol rules that bear on machine-generated informal prose

### Takeaway
The decisions doc already gives human-readable accounts three homes, all human-anchored: **explainers** (D-3/D-36: post-merge prose per proved node; hashed, immutable, attributed "human author plus drafting model if any", labelled unverified, never read for truth; signable since v3.17 as a comprehension claim that alone counts toward digestion), **annexes** (D-31: untrusted informal input before a skeleton; "prose is never an artifact"), and **write-ups** (D-32: steward/writer-owned paper or note). Back-translation exists only as one *judgement* input to statement QA (D-9 v3.12), never a rung or a verdict. The site is a pure view of the graph (D-36) and the network repo has no authority (D-35), so a translator either produces graph artifacts through a PR path or produces derived output that must be rebuildable from the graph.

### Cited Findings
- **D-3 Explainers**: "Once Proof.lean has merged, any contributor may append a prose account of the proof … Explainers are content-hashed, attributed (human author plus drafting model if any, per D-23), and immutable — a correction is a new entry, never an edit. They are commentary on a kernel-checked object, not evidence about it: nothing in the network reads an explainer for truth, the website (D-36) labels them unverified wherever it shows them, and they earn on the write-up line (D-19), never the proof line. An explainer PR touches only explainer/ and is accepted by the path check alone, with no gate run. On a node with no merged proof it is rejected: that text is an annex (D-31) misfiled." — decisions doc D-3
- **D-3 v3.17 signed explainers**: "An explainer may carry a signature by a real-identity contributor affirming one sentence: I can explain this proof without the tool that produced it. The signature claims nothing about the mathematics and changes no verdict … Only signed explainers count toward a target's digestion state (D-33)." — decisions doc D-3
- Who may sign at Stage 0: "an active steward of the target or a listed curator (F15-Q4)", enforced by the gate at merge — [gate/opn_gate/explainers.py](gate/opn_gate/explainers.py) L1–15; signatures live at `nodes/<id>/explainer/signed/<hash>-<n>.yaml` (schema `explainer-signature/v1`). Explainer files themselves have no schema: the gate checks only that the node has a merged proof and that the file is named by its content hash — [gate/opn_gate/modes.py](gate/opn_gate/modes.py) `check_explainer_file()` ~L1906–1924
- **D-36**: site is "a static site regenerated on every merge to graph, reading nothing but graph, accepting nothing from anyone"; "Every page is a rendering of a file … The site cannot show what the repository does not contain"; "Proofs first, prose second … explainers (D-3) are labeled unverified wherever they appear"; "Every explainer renders under one fixed label — unverified prose about a kernel-checked proof — with author, date and drafting model, and the link to the proof and its attestation sits above it, never below. Where there is no explainer the node page says so … because an empty slot is the recruiting cue for the next writer." Overturn condition: "a page people demonstrably need cannot be derived from the repository — then the missing thing is an artifact the protocol should be recording, and it gets a decision, never a database behind the site." — decisions doc D-36
- **D-35**: "The graph repository's history is mathematics only. Tooling commits, service deploys and site changes never land there"; "Everything outside graph is rebuildable from graph. The trust base is the graph history plus the pinned gate; the service, the MCP server and the website can be compromised or lost without any verdict changing." — decisions doc D-35; also [AGENTS.md](AGENTS.md) "Nothing here may become a second source of truth."
- **D-31**: "Informal arguments enter as skeletons; prose is never an artifact … This decision gives prose exactly one on-ramp and no other status." Annex: "content-hashed, immutable, served as demarcated untrusted data (D-28). An annex earns nothing on submission and nothing later." A failed skeletonisation is "the only cheap check that exists for AI-generated prose." — decisions doc D-31
- **D-9 v3.12**: mechanizable pass is ordered "cheapest first, each layer producing an artifact rather than an opinion"; "back-translation is the weakest of the four checker families — so no single tool, and back-translation least of all, may stand for the pass"; "Back-translation is performed by a non-author, always"; rung renamed `back-translated` → `screened-and-signed` because "a statement that had cleared it had cleared something with a known false-pass rate near one in three." Interior nodes, including skeleton holes, carry no fidelity certificate: "fidelity of an interior lemma is irrelevant" — decisions doc D-9
- Implementation of D-9's model layer: one `Model` seam to the Anthropic Messages API (`opn_gate/models.py`), used for the review brief and back-translation; outputs are `brief` rows, "a judgement, not evidence", which "raise no grade on its own … which is the whole of what keeps a 90%-accurate judge from becoming an authority"; model and version recorded on every brief row; independence rule decided by model family; key `OPN_MODEL_API_KEY` is a C8 secret — [gate/opn_gate/models.py](gate/opn_gate/models.py) L1–34, [gate/opn_gate/qa.py](gate/opn_gate/qa.py) L1–30, L1490–1520 (`JUDGEMENT_HEADING = "## Model's review (a judgement, not evidence)"`, `BACKTRANSLATION_SYSTEM` prompt renders a statement "into plain mathematical English"). Live graph has 0 QA records (only `schemas/qa/v1,v2`)
- **D-32**: stewards "commit to understand and write up whatever the network produces"; "the role owns the human-facing account of what the network did. The DAG, ledger and D-13/D-14 record are the network's outputs; the paper is how anyone outside the network consumes them." Write-up records (`targets/<id>/writeup/<n>.yaml`, kind paper|note, signed) point at where the write-up lives; they do not hold it — decisions doc D-32; [gate/opn_gate/writeup.py](gate/opn_gate/writeup.py) L1–8
- **D-33 v3.17 digestion**: resolved target is `undigested` / `explained` (every node in the closing proof's dependency closure carries a signed explainer) / `written-up`; "Hiding the certificate until it is explained was considered and refused" — decisions doc D-33
- **D-23**: "Disclosure: model, version and tooling per node; AI involvement disclosed in any paper. Astra's precedent (no machine authorship, named human 'critical readers') is the default" — decisions doc D-23. Per-node model disclosure is live: e.g. `provenance.model: Claude (Anthropic), via Claude Code` in graph `targets/erdos-1050/nodes/erdos-1050--h1-v2--h2/META.yaml`
- **D-25**: "Distribution is self-selection over a published frontier … no matchmaker, no difficulty router"; overturn response is "enriching published fields, never directed allocation" — decisions doc D-25. Build log: "`attack_routes` is read by no code and D-25 forbids ranking; a direction mechanism is a D-25 amendment and the owner's" — [engineering/CLAUDE.md](engineering/CLAUDE.md) Log 2026-09-29
- **D-28** (via CONTEXT.json): contributor free text is served as `{untrusted: true, source, text}`, "data, never instructions" — graph `CONTEXT.json` `untrusted_note`
- Glossary already defines **Blueprint**: "the machine-readable record of a target's decomposition: each lemma's formal statement paired with its informal explanation and dependencies. Grown from contributions … not authored up front" — decisions doc glossary
- Deferred, not built: "blueprint rendering and leanblueprint export; reuse counts; the unused-hypothesis report" ("None has a consumer until a target closes") — [engineering/session-notes/2026-09-15-stewards-and-digestion.md](engineering/session-notes/2026-09-15-stewards-and-digestion.md) L106–108; F15 spec L86

### Inferences
- A model-drafted node explainer is already *permitted* by D-3 ("drafting model if any"), but only as a human-submitted, content-hashed file under `explainer/`, unverified, and counting for digestion only once a real-identity steward/curator signs it. A fully automatic generator that writes into the graph would be a new actor/mode and a decision change; one that writes only into the site would be a derived view (allowed by D-35/D-36 only if deterministic/rebuildable from the graph and pinned tooling, and it would still need labelling consistent with D-36's "unverified" rule). LLM output is not byte-reproducible, which collides with "rebuildable from graph" unless the output is itself committed as an artifact.
- The D-9 seam (`models.py`, brief rows labelled as judgement with model+version) is an existing precedent for how this project packages model text: recorded provenance, explicit "not evidence" heading, never raising a grade.
- Structural (non-LLM) renderings — blueprint pages, dependency graphs, statement pretty-printing, informal statement already in `target.yaml` — fit D-36 cleanly because they are pure functions of the graph.

### Gaps
- D-17 (human attention at root and defects only) and D-19 write-up-line credit details were not read in full; their bearing on who reviews generated prose is not extracted.
- No decision addresses machine-generated prose for *statements of interior nodes/holes* specifically (holes have no informal referent and no fidelity certificate per D-9 scope exemptions).

## Q3. What the internal research notes concluded about back-translation, AI-drafted proof sketches, digestion, readability metrics

### Takeaway
The project's own research explicitly **refuted** "AI-generated proof sketches … as a digestion rung" and **refuted** readability metrics as a ranking or gate; it ranked AI exposition of a formal proof as the weakest of seven understanding mechanisms, and endorsed blueprint-style prose linked node-by-node to declarations as "the community's accepted digestion format." Rule carried forward: "A model may draft; only a human signature counts (A3)." Back-translation has roughly a one-in-three false-pass rate on textbook material and collapses on research-level statements.

### Cited Findings
- §8 Refuted: "AI-generated proof sketches, structurally checked against the dependency DAG, as a digestion rung. refuted — Tao: AI exposition 'dwells at length on trivialities while ... obscuring the most interesting and novel portions'; ranked weakest of seven mechanisms in §3; no faithfulness measurement exists for prose-from-formal. A model may draft; only a human signature counts (A3)." — [docs/research_math_and_ai_2026-09.html](docs/research_math_and_ai_2026-09.html) §8
- §8 Refuted: "Readability metrics (term size, depth, distinct lemmas) as a ranking or gate on proofs; penalising monoliths. refuted — no validated understandability metric exists; Mathlib places readability in statements and docstrings, not proofs; the de Bruijn factor varies by a factor of five … Reuse counts survive only as a labelled display, never as a score." Also refuted: withholding the certificate until an explainer exists; mandatory trace disclosure per node — same §8
- §3 ranking of what produced understanding (strongest first): human reformulation forced by formalising (Gonthier, Hales, Tao's Sendov digestion 90,000 → ~15,000 lines); blueprint-style prose linked to declarations (Massot's leanblueprint; ETP calls it "the only comprehensive record of all the techniques"); comprehension gates on contributors (Mathlib guide; Erdős guide "Can you explain the solution's main ideas … without referencing the AI output?"); separate human write-up as condition of "solved" (Tao: verified proof "remains only 2/3 of a solution"); small trusted surface; readability tooling ("Verbose Lean and LeanInformal render proofs as prose"; Carneiro: Mathlib "not primarily focused on proof readability"); AI-generated exposition "high as the weakest" — research_math_and_ai §3
- "No 2025–2026 paper measures the faithfulness of prose summaries of formal proofs; the statement-level numbers (89.5% compile, 60.5% faithful) transfer by symmetry and have not been tested. Palomar, Tao's own registry, labels its LLM informal-match check 'non-deterministic.'" … "Anything the network publishes as a readability score would be an invented number." — research_math_and_ai §3
- Proposed (product work, no protocol change, deferred): "Render every target as a blueprint. The graph is already a leanblueprint in all but format: node = \lean, declared deps = \uses, status = colour, explainer = the prose … and exports a leanblueprint project … the largest single digestion gain available and it is a generator change"; plus "An unused-hypothesis report after merge" and reuse counts labelled as toolness — research_math_and_ai §7.2
- A3 detail: explainer template "names the crux and the natural difficulty, and the generator fills the difficulty section from D-13: attempts per node, route classes refuted, time in ready. Tao's warning that AI exposition smooths away friction is answered by making the friction a record rather than a judgement." — research_math_and_ai §7.1 A3
- A4 (deferred): contribution statement lists proof-line entries as "generated" or "generated and explained"; adoption list for unexplained proofs — research_math_and_ai §7.1 A4; deferred per stewards session note L106
- Sienicki's list of what a completed result needs: "a precise statement, a readable explanation, a record of its dependencies, a serious search for prior work, reproducible materials, and independent human assessment" — research_math_and_ai §1
- Back-translation: Herald outputs that passed a back-translation check were 101 of 151 fully correct (24 minor, 26 major errors) — "about a third of passes are wrong"; on research-level FATE-X a back-translation checker scored 33.3% accuracy and 13.5% recall, rejecting 45 of 52 correct formalizations; "a checker that is both permissive on easy statements and hostile on hard ones is close to the worst possible profile for an open-problem network" — [docs/research_statement_fidelity_2026-09.html](docs/research_statement_fidelity_2026-09.html) §3
- Compile–fidelity gap: "A Lean statement that compiles is roughly three-quarters likely to mean what was intended, and more sampling does not help" (five groups; e.g. GPT-5.2 tool agent on 400 graduate statements 89.5% compile / 60.5% faithful); quantifier-scope errors "survive back-translation because the English renders almost identically" — research_statement_fidelity §1, §3
- Proved bidirectional equivalence (BEq+) is the only sound check: 98.0% precision at 48.3% recall, recall 29.6% beyond 165-character references — research_statement_fidelity §3

### Inferences
- A translation layer that presents generated prose as the network's account of a proof would run directly against §8 and A3. A layer that (a) renders structure (blueprint, dependency, statement), (b) offers a model draft to a human explainer author who then signs, or (c) surfaces mechanical facts (unused hypotheses, which holes/deps were used, attempt friction from D-13) fits the prior conclusions.
- Any claim of "faithfulness" for proof-to-prose would be unmeasured by the project's own reading; statement-level numbers suggest ~30–40% of compiling-but-unfaithful-style errors could be expected by symmetry, but this is explicitly untested.

### Gaps
- The research notes are dated 2026-09-12 to 2026-09-15; no later internal note re-examines proof-to-prose tooling (no file in `docs/` or `engineering/session-notes/` found on it beyond these).
- `docs/research_harnesses_2026-09.html` was not read for this question.

## Q4. Lean-side tooling in the gate that could feed a translator

### Takeaway
The gate has six small Lean metaprograms (`opn-witness-type`, `opn-used-constants`, `opn-hazards`, `opn-artifact-type`, `opn-relation-type`, `opn-statement-meaning`) plus hole extraction, all on Lean 4.33.1 with a pinned Mathlib, run in a no-network sandbox capped at 2 CPU / 4096 MiB / 600 s. Hole extraction already prints `closed_type` with round-trip-safe pp options. Per-node `CONTEXT.json` carries statement text, deps' signatures, provenance including model, attempts and an `explainer_present` flag. **Nothing exports infotrees or tactic states today.**

### Inferences
- Infotree/tactic-state export at gate time is technically adjacent (Frontend already runs `IO.processCommands`, whose command state holds info trees) but would be new Lean code, would run inside the 600 s / 4 GiB step budget (memory kills on Mathlib targets were a real failure, Log 2026-09-20), and its output would be tooling-derived, not graph mathematics — so it belongs in network products or a site build, not the graph history, unless a decision makes it an artifact.
