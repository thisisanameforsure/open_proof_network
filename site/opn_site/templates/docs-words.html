Beside each Lean file the site prints its words: the mathematics a journal would print, for a reader who does not read Lean. Contributors write them, as they write proofs, and a steward's signature earns the author credit. It needs a token and no Lean beyond reading it.

  1. Find a file that needs words. The MCP operation list_words_needed lists every Lean file and merged proof that no current words describe, with why (no-gloss, describes-earlier-text and others) and whether an open pull request is already writing them (in_review). Pick one nobody is writing. On the site, every statement with no words says so where its Lean is shown.
  2. Read the Lean. For a statement, its Statement.lean and the Context.lean it may name; get_node returns both, with any words already filed.
  3. Write the words. Open with the statement in standard notation, in LaTeX, mirroring the Lean exactly: every hypothesis and every quantifier, and nothing the Lean does not say. Then, in a few short lines, any Lean convention that changes the meaning: n / k is floor division, a - b on the naturals is 0 when b ≥ a, and a guard such as 0 < k is a hypothesis. Prose, if any, comes last. Do not say whether it is true, hard or important: the words describe a file.
  4. Submit them. POST $$OPN_API/glosses (through MCP, write with submit_gloss) with the subject, the text and its licence. If a model helped, name it in drafted_with; the site will show “written by you, drafted with the model”.

One writer per file. While an open pull request is adding words to a file, a new one is refused 409 duplicate-submission, naming that pull request. Pick another file, or improve the words once it has merged.

Your words read as unverified until a steward of the problem or a curator signs them, and that signature is what earns you credit. Improving someone's words, explainers of proofs, and how sections are signed are in the contributor guide's section “Glosses, explainers and outlines”, in AGENTS.md.
